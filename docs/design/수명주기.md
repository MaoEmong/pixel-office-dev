# 수명 주기 — 앱 · 데몬 · AI 세션을 한 몸으로 (T46)

- 날짜: 2026-09-21
- 상태: **확정** (Fable 설계 · 구현은 Opus). 결정 번호 **D-47** — D-02("데몬은 앱과 분리된 상주 프로세스")의 **기본 동작을 뒤집는다.**

## 요구 (사용자, 2026-09-21)

> 플러터 앱을 실행하면 데몬 프로세스가 같이 실행되도록. 데몬이 갑자기 죽어버렸을 때 처리도 해야 하고, 앱을 종료할 때 데몬도 같이 죽어야 한다.
> 이 과정에서 데몬에 연결된 agent 세션들도 같이 동작해야 한다 — 데몬이 갑자기 죽으면 떠 있던 세션들의 연결을 못 찾는 문제를 해결해야 하고, 앱을 종료하면 데몬에 연결된 세션들도 다 닫혀야 한다.

## 한눈에

```
앱 켜짐 ──▶ 데몬이 없으면 앱이 직접 띄운다(창 없이) ──▶ 데몬이 어제의 조직을 조용히 다시 출근시킨다
앱 꺼짐 ──▶ 데몬에 "정리하고 꺼져라" ──▶ 데몬이 AI 세션을 전부 닫고 꺼진다 ──(안 꺼지면)──▶ 앱이 강제로 끈다
앱이 비정상 종료 ──▶ 데몬이 "부모가 사라졌다" 를 알아채고 스스로 같은 정리를 한다
데몬이 비정상 종료 ──▶ 앱이 알아채고 다시 띄운다 ──▶ 새 데몬이 남은 AI 프로그램을 치우고, 같은 대화를 이어서 다시 띄운다
```

## 원칙

1. **앱이 주인이다.** 사용자가 보는 것은 앱 하나다. 데몬과 AI 세션은 앱의 부속으로 같이 켜지고 같이 꺼진다.
2. **어느 쪽이 먼저 죽어도 남는 것이 없어야 한다.** 고아 프로세스(주인 없는 `claude.exe` / `codex.exe` / `node.exe`)를 남기지 않는다.
3. **끊긴 가짜 터미널은 다시 붙잡을 수 없다**(운영체제 제약 — node-pty 는 재부착을 지원하지 않는다). 그래서 "연결을 되찾는다" = **남은 프로그램을 치우고, 같은 대화를 `--resume` 으로 이어서 새로 띄운다.** 대화 기억은 CLI 가 파일로 갖고 있어 사라지지 않는다.
4. **되살릴 때 쓸데없이 토큰을 쓰지 않는다.** 하던 일이 있던 캐릭터에게만 "이어서 해라" 를 타이핑한다. 쉬고 있던 캐릭터는 말없이 자리에 앉힌다.

## 1. 앱을 켜면 데몬이 같이 켜진다

- 앱 기동 시 `daemon.json` 을 읽어 붙어 본다(기존). **2초 안에 못 붙으면 앱이 데몬을 직접 띄운다** — 지금의 "데몬 시작" 버튼을 누른 것과 같지만 자동이고 **콘솔 창이 뜨지 않는다.**
  - 실행: `dev/daemon` 을 기존 `findDaemonDir` 로 찾아 `node` 로 띄운다(`npm start` 가 하는 일과 동일). 자식 프로세스로 들고 있고, 표준 출력·오류는 `<데이터 폴더>/daemon.log` 에 이어 쓴다(최근 1MB 만 유지).
  - 환경변수 `PIXEL_PARENT_PID=<앱 pid>` 를 넘긴다(§3).
  - 이미 도는 데몬이 있으면(콘솔에서 띄웠거나 지난번 것이 남아 있으면) 새로 띄우지 않고 그대로 붙는다.
- 오버레이 문구: `사무실을 여는 중…`(띄우는 중) → 붙으면 사라짐. 10초 안에 못 붙으면 `데몬을 시작하지 못했습니다` + `daemon.log` 마지막 8줄 + `다시 시도`. "데몬 시작" 버튼은 이 실패 화면에만 남는다.
- **앱은 한 번에 하나만.** 두 번째로 켜면 "이미 실행 중입니다" 를 보이고 끝낸다(데이터 폴더의 잠금 파일 + pid 생존 확인). 창이 둘이면 한쪽을 닫을 때 다른 쪽의 데몬이 죽기 때문이다.

## 2. 앱을 끄면 전부 같이 꺼진다

- 창 닫기(X · Alt+F4 · 작업 표시줄 닫기)를 가로챈다(`AppLifecycleListener.onExitRequested`). 순서:
  1. 일하는 중인 캐릭터가 있으면 확인 한 번: `일하는 중인 캐릭터가 N명 있습니다. 닫으면 전부 멈춥니다. (다음에 켜면 이어서 합니다)` — [닫기] [취소]. 없으면 묻지 않는다.
  2. 데몬에 `daemon.shutdown` 을 보낸다. 데몬은 **모든 AI 세션을 정중히 닫고**(Claude `/exit`, Codex Ctrl+C, 확인용 세션 포함) → 안 닫히면 강제 종료 → DB 를 닫고 → `daemon.json` 을 지우고 끝난다.
  3. 앱은 데몬 프로세스가 사라질 때까지 **최대 8초** 기다린다(그동안 `정리하는 중…`). 넘으면 프로세스 트리를 강제 종료(`taskkill /T /F`)한다.
  4. 앱이 끝난다.
- 앱이 직접 띄운 데몬이 아니어도(콘솔에서 띄운 것) 똑같이 끈다 — 규칙이 하나여야 예측 가능하다. 예외는 개발용 환경변수 `PIXEL_KEEP_DAEMON=1` 과 아래 설정뿐.
- **설정 "앱을 닫아도 계속 일하기"**(기본 꺼짐, `app-ui.json`): 켜면 닫을 때 데몬을 끄지 않고 §3 의 부모 감시도 하지 않는다 — D-02 의 옛 동작. 나중에 모바일 앱을 붙일 때 쓸 자리다.

## 3. 앱이 갑자기 죽으면 — 데몬이 알아챈다

앱이 강제 종료되거나 크래시하면 §2 의 코드는 실행되지 못한다. 그래서 **데몬이 부모를 지켜본다.**

- `PIXEL_PARENT_PID` 가 있으면 데몬은 **2초마다** 그 pid 가 살아 있는지 본다. 사라지면 `부모 앱이 사라졌다` 를 로그에 남기고 §2-2 와 같은 정리를 한 뒤 끝난다.
- pid 재사용 오판을 막기 위해 pid 와 함께 **프로세스 시작 시각**을 기동 때 한 번 읽어 두고 같이 비교한다(읽기에 실패하면 pid 만 본다).
- 앱이 다시 붙으면서 `hello{parentPid}` 를 보내면 감시 대상을 그 pid 로 바꾼다(앱만 재시작된 경우).

## 4. 데몬이 갑자기 죽으면 — 앱이 다시 띄우고, 세션을 되찾는다

- 앱은 두 가지로 알아챈다: 자식 프로세스 종료 알림(직접 띄운 경우) · 웹소켓 끊김 + `daemon.json` 의 pid 가 죽어 있음(붙기만 한 경우).
- **자동 재시작**: 즉시 1회, 실패하면 2초 · 5초 · 10초 간격으로 **최대 4회**. 그 뒤에는 실패 화면(§1)으로. 1분 안에 3번 죽으면 재시작을 멈추고 `데몬이 반복해서 종료됩니다` + 로그 — 죽는 원인을 덮지 않는다.
- 오버레이: `데몬이 멈춰 다시 시작하는 중 · 세션을 복구합니다` + 진행 표시.
- **새 데몬이 기동하며 하는 일**(이미 있는 D-17 · T09 · T36 위에):
  1. DB 에 적어 둔 `child_pid` 들 중 **살아 있는 것을 전부 치운다**(캐릭터 세션 + 확인용 세션). 강제 종료된 데몬은 자식을 데리고 죽지 못하므로 주인 없는 AI 프로그램이 남아 있을 수 있다. 치우기 전에 그 pid 가 정말 그 CLI 인지(실행 파일 이름) 확인한다.
  2. **트리 순서로**(부장 → 팀장 → 팀원) 같은 세션 id 로 `claude --resume` / `codex resume` 한다.
  3. 하던 일이 있던 캐릭터(진행 중 task · 답을 기다리던 질문)에게만 `[RESUMED]` 상황 안내를 타이핑한다. 쉬고 있던 캐릭터는 **말없이** 앉힌다(토큰 0).
  4. 허가 요청은 만료된다(붙잡고 있던 센서 프로세스가 같이 죽었다) → "다시 지시 필요" 카드. 질문은 그대로 유지.
  5. 상사를 되살리지 못한 부하는 오류 포즈 + 재고용 버튼(기존).
- 앱은 다시 붙어 스냅샷을 받고, 되살아난 캐릭터에 `↻ 복구됨` 을 띄운다(기존).

## 5. 앱을 다시 켜면 — 어제의 사무실이 그대로

§2 로 정상 종료한 뒤 앱을 다시 켜면 **조직이 그대로 출근해 있어야 한다.** 지금은 정상 종료 때 쉬고 있던 캐릭터가 "퇴근" 으로 남아 매번 재고용해야 한다(T41 실기에서 확인). 바꾼다:

- 데몬이 종료할 때 살아 있던 캐릭터를 `exited` 가 아니라 **`suspended`**(잠시 닫힘)로 적는다. 사용자가 퇴근시킨 것 · 상사가 내보낸 것 · 오류로 죽은 것과 구별한다.
- 다음 기동 때 `suspended` 캐릭터를 §4-2~3 과 똑같이 되살린다 — **전부 말없이**(정상 종료였으니 하던 일이 없다. 있었다면 그 task 는 종료 시점에 `aborted` 가 아니라 **그대로 두고** `[RESUMED]` 로 이어 준다).
- 부서가 여럿이면 **지금 보고 있는 탭의 부서부터** 되살리고 나머지는 뒤이어. 한꺼번에 띄우는 CLI 는 최대 3개(기동 부하).
- 되살리기에 실패한 캐릭터(세션 파일이 사라짐 등)는 오류 포즈 + 재고용.

## 상태 · 와이어 변화

- `members.status` 에 `suspended` 추가(스키마 추가 변경). 앱에서는 회색 + 모니터 `(잠시 닫힘)` — 되살아나는 동안만 잠깐 보인다.
- `hello` 파라미터에 `parentPid?` 추가. `daemon.shutdown` 응답에 `{closing: N}`(닫는 세션 수).
- 새 알림 `daemon.notice{kind:'parent-gone'|'recovering', …}`(로그·오버레이용).
- PROTOCOL.md 에 "수명 주기" 절.

## 검증 (T46-3 실기)

1. 앱만 실행 → 콘솔 창 없이 데몬이 뜨고 사무실이 열린다(시간 측정).
2. 부서 + 부장 + 팀원 하나를 만든 뒤 앱을 X 로 닫는다 → 8초 안에 `node.exe` · `claude.exe` · `codex.exe` 가 **하나도 남지 않는다.**
3. 앱을 다시 켠다 → 조직이 그대로 출근, 대화 기억 유지(이전 대화 내용을 물어 확인), 토큰을 쓰지 않았는지 사용량 표로 확인.
4. 일하는 도중에 데몬을 `taskkill /F` → 앱이 자동으로 다시 띄우고, 남은 AI 프로그램이 치워지고, 캐릭터가 되살아나 하던 일을 잇는다. 허가 대기 중이었다면 "다시 지시 필요".
5. 앱을 `taskkill /F` → 데몬이 몇 초 안에 스스로 정리하고 끝난다. 남는 프로세스 0.
6. 데몬을 1분 안에 3번 죽인다 → 재시작을 멈추고 로그를 보여 준다.
7. 앱을 두 번 실행 → 두 번째는 안내 후 종료.
8. 설정 "앱을 닫아도 계속 일하기" 를 켜고 닫는다 → 데몬과 세션이 남는다(옛 동작).

## 범위 밖

- 윈도우 작업 개체(Job Object)로 묶어 운영체제 수준에서 같이 죽게 하기 — 부모 감시로 충분한지 써 보고 판단.
- 데몬을 실행 파일 하나로 묶어 앱에 동봉하기(지금은 저장소의 `dev/daemon` 을 찾아 `node` 로 띄운다).
- 모바일 클라이언트(그때 "계속 일하기" 설정이 기본이 된다).
