## 원칙 (D-48)

1. **언어·구조는 그대로.** 노드 데몬 + 플러터 앱 + 웹소켓. 맥용으로 다시 쓰는 것이 아니라 **운영체제에 닿는 곳만** 분기한다. (node-pty·xterm·MCP·SQLite·ws 는 전부 맥에서 돈다. node-pty 는 원래 유닉스용이 먼저다.)
2. **운영체제에 닿는 코드는 파일 하나에 모은다.** 데몬 `src/platform.ts`, 앱 `lib/platform/platform.dart`. 나머지 코드는 `platform.xxx()` 만 부른다. 지금처럼 `process.platform === 'win32'` 가 여기저기 흩어져 있으면 맥에서 하나씩 터진다.
3. **윈도우 동작은 1비트도 바뀌지 않는다.** 리팩터링이지 기능 변경이 아니다 — 기존 테스트 전부 그대로 통과해야 한다.
4. **맥 분기는 이 PC 에서 단위 테스트로만 검증한다**(플랫폼을 주입해서). 실제 맥에서만 알 수 있는 것은 추측하지 말고 **"맥에서 확인" 목록**에 적는다. 이 프로젝트의 규칙 그대로(0단계 실측·T23 Codex 이월 목록).
5. **리눅스는 덤.** 맥 분기 = 유닉스 분기로 쓰되(`ps`·`kill`·`~/.config`), 리눅스 실기는 하지 않는다.

- **T48-1 데몬**: `src/platform.ts`(데이터 폴더 · 실행 파일 탐색 뿌리 · 프로세스 생존/이미지 이름/트리 종료 · 부모 시작 시각 · 안내 문구) 로 모으고 모든 호출처를 바꾼다. 유닉스 분기 구현(위 표). 위험 명령 판별에 유닉스 패턴 추가(플랫폼 무관). hook/statusline 경로 인용. `SIGHUP`. tui-map 로더의 플랫폼 접미사 규칙. 단위 테스트: 플랫폼을 `'darwin'` 으로 주입해 각 항목을 고정(`ps`/`kill` 은 스폰을 가짜로 바꿔 인자를 검사), 윈도우 테스트는 그대로. `npm test` 전부 통과.
- **T48-2 앱**: `lib/platform/platform.dart` 로 모으고 호출처 교체, 유닉스 분기, `node` 절대 경로 탐색, 맥 단축키, `flutter create --platforms=macos .` 로 `macos/` 러너 추가 + 엔타이틀먼트(샌드박스 off, 파일 선택) + 초기 창 크기, `file_selector_macos` 는 `file_selector` 가 자동으로 끌어온다(pubspec 확인). 위젯 테스트: `Platform` 을 주입 가능하게 해서 맥 분기 검증(`debugDefaultTargetPlatformOverride` + 주입한 platform 객체). `flutter analyze && flutter test` 통과. **맥 빌드는 이 PC 에서 못 한다** — `flutter build macos` 는 2단계.
