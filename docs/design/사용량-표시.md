# 사용량 표시 (T43) — 설계

- 날짜: 2026-09-21
- 상태: **확정** (Fable 설계 · 구현은 Opus). 근거 실측: `docs/worklog/T43-0-UsageSpike.md`, 원자료 `dev/spike-1/out/`
- 결정 번호: D-45

## 요구 (사용자, 2026-09-21)

> 플러터 앱에서 각 ai별 남은 주간 사용량 체크도 확인 가능했으면 좋겠어. 연결 안되있으면 그냥 연결 안되있다고 뜨면 되는거고.
> 각 llm별 사용량 확인이 되어야 하고 각 유닛 별 사용량, 컨텍스트 양 등 플러터 앱을 통해서 이런 사용 데이터를 확인할 수 있어야 한다.

세 가지다: ① **엔진별(Claude / Codex) 주간 남은 사용량**, 안 붙어 있으면 "연결 안 됨" ② **캐릭터별 사용량**(누적 토큰) ③ **캐릭터별 컨텍스트 양**.

## 원칙 (D-45)

1. **로그인 토큰·자격 증명 파일을 읽지 않는다. 회사 서버에 직접 묻지 않는다.** 이 툴은 "구독 CLI 를 그대로 띄워 쓰는" 툴이다(D-01). 쓰는 출처는 CLI 가 스스로 내주는 것뿐 — 상태 줄(statusLine) 페이로드, CLI 가 쓰는 기록 파일, 센서(hook) 페이로드, 무해한 하위 명령(`auth status` / `login status`).
2. **계정 이메일은 저장도 표시도 하지 않는다.** 연결 여부와 요금제 이름만.
3. **부호를 하나로 맞춘다.** Claude 는 "쓴 비율", Codex 화면은 "남은 비율" 로 말한다. 데몬 안에서는 전부 `usedPercent`(0~100), 앱은 전부 **"남음 N%"** 로 보여 준다(사용자 표현이 "남은 사용량").
4. **멤버 세션에 슬래시 명령(`/usage`, `/status`)을 밀어 넣지 않는다.** 일하는 AI 의 화면을 건드리지 않는다.

## 데이터 출처 (실측 결과 그대로)

| 데이터 | 출처 | 언제 갱신 |
|---|---|---|
| Claude 주간 · 5시간 한도 | 세션 `--settings` 에 주입한 **statusLine 명령**의 페이로드 `rate_limits.seven_day` / `five_hour` `{used_percentage, resets_at}` | 그 세션의 턴이 끝날 때(이벤트). **첫 호출 전·`--resume` 직후에는 키가 없다** |
| Claude 멤버 컨텍스트 | 같은 페이로드 `context_window{used_percentage, context_window_size, current_usage}` | 이벤트 |
| Claude 멤버 누적 토큰·비용 | transcript(센서가 주는 `transcript_path`)의 마지막 `type:"cost-state"` 줄 — `modelUsage` 모델별 토큰 + `totalCostUSD`. 폴백: statusLine `cost.total_cost_usd` | `Stop` 센서 직후 |
| Claude 연결·요금제 | `claude auth status` JSON 의 `loggedIn` · `subscriptionType` (약 0.3초) | 60초 폴링 + 기동 시 |
| Codex 주간 한도 | 센서가 주는 `transcript_path`(rollout 파일)의 마지막 `token_count` 중 **`limit_id === "codex"` 이고 `rate_limits.primary != null` 인 것** — `primary{used_percent, window_minutes:10080, resets_at}` | 턴마다 1개(이벤트) |
| Codex 5시간 한도 | 같은 이벤트의 `rate_limits.secondary` | 있을 때만(요금제에 따라 항상 null) |
| Codex 멤버 컨텍스트 | 같은 이벤트 `info.last_token_usage.input_tokens` / `info.model_context_window` | 이벤트 |
| Codex 멤버 누적 토큰 | `info.total_token_usage` | 이벤트 |
| Codex 연결·요금제 | `codex login status` (약 0.06초) | 60초 폴링 + 기동 시 |
| Codex 비용(USD) | **없음** — 토큰만 | — |

**빈 `token_count` 함정**: `limit_id:"premium"` + `info:null` + `primary:null` 인 이벤트가 섞인다. 조건에 맞는 **마지막 것**을 고른다. rollout 은 파일 끝에서 64KB 만 읽는다(전체를 읽지 않는다).

**아는 한계와 대응**

- Claude 의 한도 숫자는 **그 엔진의 멤버가 한 턴이라도 돌아야** 들어온다. → 엔진 사용량을 DB 에 남겨 두고 **마지막으로 확인한 값 + "N분 전"** 을 보여 준다. 한 번도 못 봤으면 "첫 작업 후 표시".
- 위 한계만으로는 **아무도 일하지 않았을 때·툴 밖에서 사용량을 썼을 때 숫자가 어긋난다**(사용자 지적, 2026-09-21: "남은 사용량 확인이 제대로 안 되는 거겠네"). → **확인용 세션(T43-4)** 으로 메운다. 아래 절.
- statusLine 은 세션당 하나라 **사용자 전역 statusLine 설정은 이 툴이 띄운 세션에서만 덮인다**(데몬 소유 세션이라 수용). 우리 스크립트는 터미널 탭 하단에 한 줄을 돌려준다: `컨텍스트 37% · 주간 45% 남음`.
- CLI 가 업데이트되어 필드 이름이 바뀌면 해당 값만 "알 수 없음" 으로 떨어지고 나머지는 계속 돈다(파서는 필드별로 방어적으로).

## 확인용 세션 (T43-4) — 턴이 없어도 맞는 숫자

실측: 새 세션에서 `/usage` 만 치면 **모델 턴 0 · 토큰 0** 으로 주간 한도가 그대로 나온다(Claude). Codex 는 `/status`.

- 데몬이 기동할 때 **연결된 엔진마다 확인 전용 세션을 하나** 띄운다. 멤버가 아니다 — DB 의 `members` 에 넣지 않고, 사무실에 나타나지 않고, 센서(hooks)·팀 도구(MCP)·statusLine 을 주입하지 않고, 지시를 받지 않는다. cwd 는 데몬 데이터 폴더 아래 전용 빈 폴더(`usage-probe/<engine>`), 첫 실행 신뢰 다이얼로그는 기존 ScreenModel 감지로 통과.
- **5분마다**(`PIXEL_USAGE_PROBE_SEC`, 기본 300) 슬래시 명령을 치고 화면을 읽은 뒤 `Esc` 로 닫는다. Claude: `/usage` → `Current session` · `Current week (all models)` · `Current week (<모델명>)` 의 `N% used` + `Resets …`. Codex: `/status` → `Weekly limit` · `5h limit` 의 `N% left` + 리셋, **뷰포트가 아니라 스크롤백 전체**를 읽는다(인라인 렌더라 잘린다). 모델 이름은 하드코딩하지 않는다 — 괄호 안 문자열을 그대로 라벨로.
- 화면 패턴은 `tui-maps/<engine>-<ver>.json` 의 `usage` 절에 둔다(버전별 교체). **패턴이 안 맞으면 값을 버리고 `daemon.notice{warn}` 한 번** — 턴 종료 출처(statusLine · rollout)가 계속 값을 대 주므로 기능은 죽지 않는다.
- 출처 우선순위: 같은 값에 대해 **더 최근 것**이 이긴다(확인용 세션 5분 주기 vs 턴 종료 이벤트). 엔진 사용량에 `source: "probe" | "turn"` 을 남긴다.
- 기동에 약 60초 걸린다 → 그동안은 DB 의 마지막 값 + "N분 전". 확인용 세션이 죽으면 백오프(1분 → 최대 10분) 후 다시 띄우고, 엔진이 `connected:false` 면 띄우지 않는다.
- 와이어 추가: `engines[].models: [{ "label": "Fable", "usedPercent": 31, "resetsAt": "…" }]`(없으면 빈 배열), `engines[].source`. 앱 팝오버의 엔진 블록에 모델별 막대를 한 줄씩 더한다.
- 끌 수 있다: `PIXEL_USAGE_PROBE=0`(상주 프로세스가 싫을 때) — 그러면 턴 종료 출처만 쓴다.

## 데몬

- 신규 `src/usage/UsageTracker.ts` — 엔진 사용량·멤버 사용량의 메모리 상태 + 영속. 입력 세 갈래:
  1. `HookReceiver` 새 경로 **`POST /status/<memberToken>`** — Claude statusLine 스크립트(`src/hooks/statusline.js`, hook.js 와 같은 방식: stdin JSON → POST → 응답 텍스트를 stdout 으로)가 보낸다. 응답 = 상태 줄에 찍을 한 줄.
  2. 어댑터의 턴 종료(`Stop`, Codex 는 화면 idle 폴백 포함) → Claude: transcript `cost-state` 꼬리 읽기 / Codex: rollout 꼬리 읽기.
  3. 60초 타이머 + 기동 시 → `claude auth status` · `codex login status`. 실행 파일이 없으면 `connected:false, reason:'not-installed'`, 로그인이 안 돼 있으면 `reason:'logged-out'`.
- `pty/hookSettings.ts` — Claude 세션 설정에 `statusLine{type:'command', command:'node statusline.js <port>'}` 추가(멤버 식별은 기존 `PIXEL_MEMBER`).
- 스키마 v3(추가만): `engine_usage(engine PK, json, updated_at)`, `member_usage(member_id PK, json, updated_at)`. 멤버 행은 멤버 삭제 때 같이 지운다. 엔진 행은 남긴다(마지막 값 표시용).

## 앱

시선 서열(레이아웃 v2)은 그대로다 — 사용량은 **허가 카드보다 아래, 로그와 같은 급**의 참고 정보다. 평소엔 조용하고, 위험할 때만 색이 든다.

1. **상단 바 — 엔진 칩 두 개**(데몬 pill 왼쪽): `Claude 남음 45% · 3일 뒤` / `Codex 연결 안 됨`.
   - 색: 남음 >50% 기본 · 20~50% 주황 · <20% 빨강 · 연결 안 됨 회색.
   - 값이 오래됐으면(10분↑) 끝에 `· 12분 전`. 한 번도 못 봤으면 `Claude · 첫 작업 후 표시`.
   - 클릭 → **사용량 패널**(팝오버): 엔진별 주간 막대 + 5시간 한도 막대 + 요금제 + 리셋 시각(절대·상대) + 마지막 확인 시각, 그 아래 **이 부서의 캐릭터 표**(이름 · 직급 · 엔진 · 컨텍스트 % 막대 · 누적 토큰 · 비용) — 컨텍스트 큰 순. 행 클릭 = 그 캐릭터 선택.
   - 연결 안 됨 칩의 툴팁: `codex 가 설치돼 있지 않습니다` / `로그인이 필요합니다 — 터미널에서 codex login`.
2. **오른쪽 패널 헤더 — 선택 캐릭터의 사용량 한 줄**(cwd 줄 아래): `컨텍스트 ▓▓▓░░░░░ 37% (74k / 200k) · 토큰 358k · $1.84`.
   - 컨텍스트 막대 색: <70% 기본 · 70~89% 주황 · ≥90% 빨강(곧 자동 요약이 일어난다는 뜻). Codex 는 비용 자리 없음.
   - 아직 값이 없으면 `사용량 — 첫 턴 뒤 표시`.
3. **사무실 캔버스 — 경고일 때만.** 컨텍스트 ≥70% 인 캐릭터의 책상 모니터 아랫변에 3px 막대(주황/빨강). 평소엔 아무것도 그리지 않는다(빼기 원칙).
4. 단위 표기: 토큰은 `358k` · `1.2M`, 리셋은 `3일 뒤` / `5시간 뒤` / `곧`. 툴팁에 정확한 값.
5. 테스트: 칩 상태 5종(정상·주황·빨강·연결 안 됨·측정 전)·오래된 값 표기·팝오버 표 정렬·행 클릭 선택·패널 한 줄(Claude/Codex/값 없음)·캔버스 경고 막대(69%→없음, 70%→주황, 90%→빨강)·단위 포매터.
