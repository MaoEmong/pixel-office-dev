## Problem Statement

혼자 여러 AI 코딩 에이전트(Claude Code, Codex)를 굴리면 터미널이 여러 개 떠 있고, 누가 지금 뭘 하는지·누가 허가를 기다리는지·누가 끝났는지를 놓친다. 이걸 **픽셀아트 사무실** 하나로 본다. 캐릭터 한 명 = 실제 CLI 세션 하나. 사무실 안에서 지시하고, 일하는 걸 관전하고, 허가·질문에 답하고, 보고를 받는다.

사용자 원문: "앱을 통해 명령을 하고 실제 ai들이 작업하는것을 ui로 보고 기타 등등 작업을 진행할 수 있는 나만의 개발 툴". 개인용.

**연동 방식(사용자 교정, rev 2):** "그냥 cli를 켜서 거기다가 작업 명령을 내리는 식으로 관리할꺼라니까." 즉 지금 터미널에서 `claude`/`codex`를 켜고 타이핑하는 것을 그대로, 터미널 대신 사무실 화면에서 한다. 프로그램용 SDK나 서버 인터페이스는 쓰지 않는다. 각 CLI는 사용자 본인의 구독으로 로그인돼 있고, "어차피 ai구독 안했으면 아예 못쓰는거고 그럼 문제될것도 없잖아."

핵심 요구(사용자 확정): **한 팀이 한 프로젝트를 맡고, 직급은 팀장/팀원 둘뿐.** 사용자의 명령은 팀장이 받아서 팀원에게 나눠 준다. **팀장이 오케스트레이터다.** 팀원은 팀장이 작업이 필요할 때 알아서 생성하고 삭제한다. 사용자도 **출근/퇴근** 기능으로 팀원을 추가·삭제할 수 있다. 팀장과 팀원 각각에 **개별 지시문 문서**(CLAUDE.md/AGENTS.md 격)를 따로 설정할 수 있어야 한다.

## What Makes This Cool

- **터미널을 사무실이 감싼다.** 기존 픽셀 오피스 오픈소스 4종(Pixel Agents, Claude-Office, claude-office, pixtuoid)은 hooks로 이벤트를 받아 그리기만 하고, 지시는 별도 터미널에서 해야 한다. 이 툴은 데몬이 CLI 프로세스를 가상 터미널(pty)에 직접 띄우므로 **지시·허가·질문 답변이 사무실 안에서 되고**, 캐릭터를 클릭하면 **실제 터미널 화면**이 그대로 보여 거기서 직접 쳐도 된다. 슬래시 명령도 그대로.
- **막히면 내게 온다.** 허가나 질문이 생긴 캐릭터는 "내 책상"으로 걸어와 줄을 선다. 끝나면 보고서를 들고 온다(팀 기능 전인 v1a에서는 턴 종료 시 마지막 메시지가 보고서).
- **팀과 직급.** 팀장에게 한 줄 지시하면 팀장이 팀원들에게 일을 쪼개 주고, 팀원들이 보고하고, 팀장이 취합해 사용자에게 보고한다. 위임 과정이 사무실에서 눈에 보인다.
- **엔진 혼합.** 같은 팀 안에 Claude 캐릭터와 Codex 캐릭터가 섞여 있다. 사무실은 어느 엔진인지 모른다.
- **앱을 꺼도 일한다.** CLI 프로세스는 상주 데몬이 들고 있어서 Flutter 창을 닫아도 캐릭터들은 계속 일하고, 다시 열면 이어서 본다. 나중에 모바일 앱이 같은 데몬에 붙어 밖에서 지시한다.

## Constraints

- **플랫폼:** Windows 11 우선. Flutter 데스크탑(Windows). 배포·설치 파일·CI·macOS는 범위 밖. 소스 빌드로 사용.
- **CLI는 그대로 쓴다.** 수정 없는 공식 바이너리를 사용자 본인 로그인으로 실행. 비용·한도는 지금 터미널에서 쓰는 것과 동일. 별도 API 키·SDK·서버 인터페이스 없음.
- **이 머신의 실제 환경(2026-09-14):** Node v24.14.1. Codex CLI 0.154.0(npm 전역, PATH에 있음, `hooks` 기능 stable). Claude Code 2.1.270은 데스크탑 앱 번들 `%APPDATA%\Claude\claude-code\2.1.270\claude.exe`에만 있고 PATH에 없다 → 데몬 설정에 경로를 적거나 `npm i -g @anthropic-ai/claude-code`로 PATH에 올린다(번들 경로는 앱 업데이트 시 버전 폴더가 바뀌므로 npm 설치 권장). Flutter 설치됨.
- **이벤트는 hooks로 받는다, 화면 긁기는 폴백.** Claude Code hooks(공식): `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PermissionRequest`, `Notification`, `Stop`, `SubagentStop`, `SessionEnd`. hook은 stdin으로 JSON을 받고 stdout JSON으로 결정을 돌려줄 수 있다(`PreToolUse`/`PermissionRequest`는 allow/deny 결정 가능). Codex hooks는 0.154.0에서 stable로 표시되나 **이벤트 종류·설정 형식·결정 반환 가능 여부는 미확인**(Next Steps 0). 둘 다 안 되는 경우의 폴백은 세션 트랜스크립트 파일 감시(`~/.claude/projects/**/*.jsonl`, `~/.codex/sessions/**/*.jsonl` — Pixel Agents의 "heuristic mode"와 같은 방식).
- **세션별 hook 주입은 사용자 전역 설정을 건드리지 않는다.** Claude는 실행 시 `--settings <json 파일>`로 그 세션에만 hooks를 주입(확인 필요: `--settings`가 hooks를 받는지, Next Steps 0). Codex는 `-c` 오버라이드 또는 프로젝트 단위 설정. 사용자의 `~/.claude/settings.json`에는 이미 다른 hooks가 있으므로 병합이 아니라 세션 단위 추가여야 한다.
- **디자인은 미확정.** 와이어프레임(아래)은 "팀·직급" 요구 이전에 그린 것. 사용자: "우선 디자인은 넘어가자." → /plan-design-review에서 팀 위계를 반영해 다시 잡는다.

## Premises

1. **캐릭터 = 실제 CLI 세션.** 데몬이 `claude`/`codex`를 pty에 띄우고 소유한다. 지시는 그 터미널에 타이핑된다. 터미널 화면은 언제든 그대로 볼 수 있고 직접 칠 수도 있다. (rev 1의 "TUI를 못 쓴다"는 전제는 폐기.)
2. **이벤트는 hooks 우선, 트랜스크립트 감시 폴백, 화면 파싱은 최후.** 터미널 글자를 긁어 상태를 추정하는 건 깨지기 쉬우므로 마지막 수단.
3. **핵심 자산은 엔진 중립 이벤트 모델.** 두 CLI의 hook 이벤트를 공통 "오피스 이벤트"로 정규화하는 어댑터가 설계의 중심. 사무실은 이벤트만 본다.
4. **범위: 기능 전부, 장식은 나중.** 지시·실시간 말풍선·허가·질문·보고·다중 캐릭터 병렬·팀 위임·터미널 뷰는 v1. 커피 브레이크·낮밤·사무실 편집기는 v2.
5. **Windows 우선, 배포 없음.**
6. **팀 = 프로젝트, 팀장 = 오케스트레이터.** 한 팀이 한 프로젝트(작업 디렉토리)를 맡는다. 직급은 팀장/팀원 2단. 사용자는 팀장에게만 지시하고, 팀장이 팀원을 고용·해고·위임하며, 보고는 팀원→팀장→사용자로 흐른다. 사용자는 출근/퇴근으로 팀원을 직접 추가·삭제할 수도 있다.
7. **멤버마다 자기 지시문이 있다.** 팀장과 팀원 각각에 개별 지시문 문서를 두고, 앱에서 편집하며, 세션이 시작·재개·압축될 때마다 그 멤버에게 주입된다.

## Approaches Considered

### Approach A: pty + hooks 데몬 (선택)
- Summary: Node 상주 데몬이 `node-pty`(Windows ConPTY)로 CLI를 캐릭터마다 띄우고, hooks로 이벤트를 받고, 지시·허가 응답은 pty에 키 입력으로 넣는다. Flutter는 정규화 이벤트 + 터미널 바이트 스트림을 받는다.
- Effort: M. Risk: Med (hook 결정 반환·키 입력 매핑이 CLI 버전에 따라 달라질 수 있음).
- Pros: 사용자가 원하는 모델 그대로. 구독·비용·약관 이슈 없음. 터미널 뷰가 공짜로 따라옴. Claude Squad(tmux, macOS/Linux)·AgentJuggler 같은 "CLI를 터미널 멀티플렉서로 관리" 방식이 이미 존재 — 단 Windows ConPTY 검증 근거는 아니므로 Next Steps 0에서 직접 확인.
- Cons: TUI 프롬프트(허가 메뉴 등)의 키 입력 매핑은 버전에 따라 바뀔 수 있음 → hook 결정 반환을 우선하고 키 입력은 폴백. Codex hooks 세부 미확인.
- Reuses: `node-pty`, Claude Code hooks, Codex hooks, Flutter `xterm` 패키지(터미널 렌더링).

### Approach B: 프로그램 연동 (Agent SDK / app-server) — 기각
- Summary: rev 1의 안. CLI 대신 라이브러리·서버 인터페이스로 세션을 만든다.
- 기각 사유: 사용자 의도("CLI를 켜서 명령")와 다름. 터미널 화면이 없어짐. Claude 쪽은 별도 크레딧 체계를 타서 비용 구조가 달라짐. 필요 없는 복잡도.

### Approach C: hooks만, 터미널은 사용자가 따로 — 기각
- Summary: 기존 오픈소스 방식. 사용자가 터미널에서 CLI를 켜고, 앱은 hooks로 관전만.
- 기각 사유: 지시·허가·팀 위임이 앱 안에서 안 됨. 차별점 소멸.

## Recommended Approach

**A.** 데몬은 rev 1 결정대로 Flutter와 분리된 상주 프로세스(사용자: "나중엔 밖에서 모바일앱으로 작업 진행시키고 싶거든").

### 구성 요소

```
[Flutter 데스크탑]  ──WebSocket(localhost, 토큰)──▶  [Node 데몬 "office-daemon"]
[모바일 앱 (v2)]    ──(터널/Tailscale, v2)────────▶      ├─ 레지스트리 + SQLite(팀·멤버·이벤트·pending·tasks)
                                                       ├─ PtyManager: node-pty로 멤버당 CLI 1개 (claude | codex), cwd=팀 프로젝트
                                                       ├─ ScreenModel: 멤버당 headless 터미널 에뮬레이터(@xterm/headless) — 현재 화면의 단일 소스
                                                       ├─ HookReceiver: http://127.0.0.1:7420/hook/<memberToken>  ← CLI hooks가 POST
                                                       ├─ 어댑터: ClaudeHooks / CodexHooks → 오피스 이벤트 정규화
                                                       ├─ TeamTools MCP (hire / dismiss / delegate / report / ask_user), HTTP, URL에 memberToken
                                                       └─ 멤버 지시문 저장소: %LOCALAPPDATA%\pixel-office\teams\<team>\members\<member>\INSTRUCTIONS.md
```

**1. office-daemon (Node/TypeScript)**
- WebSocket 서버(127.0.0.1:7420). 시작 시 랜덤 토큰을 `%LOCALAPPDATA%\pixel-office\daemon.json`에 써 두고 클라이언트가 제시. 로컬 전용. 원격은 v2.
- **와이어 프로토콜:** JSON-RPC 2.0. 클라이언트→데몬: `hello{token, since?}`(토큰 불일치 시 에러 후 종료; `since` 없으면 스냅샷만), `events.query{teamId, beforeSeq, limit}`, `team.create{name, cwd, leaderEngine}`(팀장 자동 출근), `team.delete`, `member.clockIn{engine, name, instructions?}`(UI 라벨 "출근" — 팀원 추가), `member.clockOut{memberId}`(UI 라벨 "퇴근" — 진행 중 task는 aborted 후처리), `member.rehire`, `member.instructions.get/set{memberId, markdown}`(개별 지시문 편집; set은 다음 세션 시작/재개/압축 시 반영, 즉시 반영은 `member.restart`), `member.restart`, `member.instruct{text}`, `member.type{bytes}`(터미널 뷰에서 직접 타이핑), `member.attach`(→ 직렬화된 현재 화면 + 스크롤백, 이후 `term` 스트림 구독), `member.detach`, `member.resize{cols, rows}`(마지막으로 attach한 데스크탑 클라이언트만 유효; 모바일 v2는 읽기 전용 축소 표시), `member.interrupt`(Ctrl+C 전송), `member.fire`, `approval.respond`, `question.respond`, `daemon.shutdown`. 데몬→클라이언트: `event`(영속, 전역 단조 `seq`), `snapshot{seq, teams, members, pending, tasks}`, `term{memberId, bytes}`(attach한 클라이언트에게만, 비영속). 클라이언트는 `seq > snapshot.seq`만 적용. (rev 1의 텍스트 델타 스트림은 pty 구조에 소스가 없어 삭제. 말풍선은 도구 호출 단위로 갱신된다.)
- **PtyManager:** 멤버 고용 시 `node-pty.spawn(cli, args, {cwd, cols, rows})`. Claude: `claude --settings <세션용 hooks json> --mcp-config <TeamTools json>` (+ `--resume <id>` 재개 시). Codex: `codex -c <hooks/mcp 오버라이드>` (+ `codex resume <id>`). `child_pid`를 SQLite에 기록. **지시 = 텍스트 + Enter를 pty에 write.** 여러 줄 지시는 붙여넣기 방식(bracketed paste)으로 넣어 TUI가 한 번에 받게 한다(동작 확인 Next Steps 0).
- **ScreenModel (M0 포함):** raw 바이트를 그대로 재생하면 TUI(커서 이동·행 지우기로 다시 그림)가 깨지므로, 멤버당 headless 터미널 에뮬레이터(`@xterm/headless` + serialize 애드온, needs verification)를 데몬에 두고 pty 출력을 전부 흘려 넣는다. 이것이 (a) `member.attach` 시 클라이언트에 보낼 직렬화 화면, (b) 책상 모니터의 "마지막 줄" 텍스트, (c) 키 입력 폴백 전 프롬프트 문구 감지, (d) **"prompt ready" 판정**(허가 다이얼로그·슬래시 메뉴·신뢰 다이얼로그가 떠 있지 않고 입력 프롬프트가 보이는 상태)의 단일 소스다.
- **입력 직렬화:** 멤버별 입력 큐 하나. 사용자 직접 타이핑(`member.type`)과 자동 타이핑(`instruct`, `[TASK]`, `[REPORTS]`, `[ANSWER]`, `[RESUMED]`)이 같은 큐를 탄다. 자동 타이핑은 hook 상태(idle, 열린 질문 없음) **그리고** ScreenModel의 prompt ready **그리고** 사용자가 직접 치는 중이 아님(마지막 `member.type` 후 3초 경과)일 때만 flush한다.
- **HookReceiver:** 각 CLI 세션에 주입한 hook 명령은 stdin JSON을 데몬의 `/hook/<memberToken>`에 POST하고 응답 JSON을 stdout으로 돌려준다. 매 도구 호출마다 Node를 기동하면 Windows에서 수십~백 ms가 붙으므로 **Windows 내장 `curl.exe --data-binary @-`**를 기본으로 쓰고(hook 명령이 어느 셸로 실행되는지·경로 인용은 Next Steps 0), 부족하면 상주 헬퍼. 결정이 필요한 이벤트(`PermissionRequest`, `PreToolUse`)는 데몬이 응답을 **사용자가 답할 때까지 보류**한다(hook `timeout`을 크게 설정; 실제 상한 확인 Next Steps 0). URL의 memberToken은 세션 간 혼선·우발적 오전송을 막는 용도이지 보안 경계는 아니다(같은 사용자 프로세스는 설정 파일에서 읽을 수 있음; 개인용이라 수용).
- **ClaudeHooks 어댑터:** `SessionStart`(session_id 저장 — 재개용; `source`가 startup/resume/clear/compact 중 무엇이든 **항상 최신 id로 갱신**해 사용자가 터미널 탭에서 `/clear`·`/resume`을 쳐도 복구 id가 stale이 되지 않게 함 — `source` 필드 존재 needs verification) / `UserPromptSubmit`(턴 시작) / `PreToolUse`(도구별 reading·editing·running 매핑; Bash·PowerShell은 팀 뮤텍스 판정) / `PostToolUse`(도구 완료) / `PermissionRequest`(→ `pending(approval)`, 응답으로 allow/deny 반환) / `Notification`(idle·허가 대기 알림) / `Stop`(→ `idle`) / `SessionEnd`(→ 종료). `AskUserQuestion`은 `PreToolUse`에서 잡아 `pending(question)`으로 만들고, 답은 (a) hook 결정으로 돌려줄 수 있으면 그걸로, (b) 아니면 TUI 메뉴에 키 입력(숫자/Enter)으로 — 어느 쪽이 되는지 Next Steps 0에서 확인.
- **CodexHooks 어댑터:** Codex hooks 이벤트를 같은 표로 매핑. **결정 반환이 안 되면** 승인 프롬프트(`y/n`)에 pty 키 입력으로 응답. hooks 자체가 부족하면 `~/.codex/sessions/**/rollout-*.jsonl` 감시로 폴백. 세션 id는 hook 페이로드 또는 rollout 파일명에서.
- **키 입력 폴백 원칙:** hook 결정 반환이 가능한 이벤트는 반드시 그걸 쓴다. 키 입력은 TUI 프롬프트 문구를 화면 버퍼에서 확인한 뒤에만 보낸다(엉뚱한 곳에 `y`가 들어가는 사고 방지). 프롬프트 문구·키 매핑은 CLI 버전별 표로 관리(`daemon/tui-maps/claude-2.1.json` 등).
- **멤버 지시문 주입:** 각 멤버의 `INSTRUCTIONS.md`(팀장은 오케스트레이션 규칙·팀원 고용 기준·디렉토리 분리 규칙, 팀원은 역할·코딩 규칙 등. 사용자가 앱에서 편집, 비어 있으면 데몬 기본 템플릿). 주입 경로: Claude는 **`SessionStart` hook의 `additionalContext` 반환**을 1순위로 — startup/resume/clear/compact 모두에서 다시 주입되므로 compaction 유실이 없다(hook이 additionalContext를 지원하는지 needs verification). 2순위 `--append-system-prompt`. Codex는 hooks의 동등 기능이 있으면 그걸로, 없으면 데몬이 세션 시작 시 `[ROLE]` 메시지로 타이핑하고 `SessionStart(compact)` 상당 시점에 재타이핑. 같은 cwd를 공유하므로 **프로젝트의 CLAUDE.md/AGENTS.md는 건드리지 않는다** — 그건 프로젝트 공통 규칙, 멤버 지시문은 그 위에 얹히는 개인 규칙.
- **TeamTools MCP (HTTP streamable):** 데몬이 `/mcp/<memberToken>`으로 노출. Claude는 `--mcp-config`, Codex는 `-c mcp_servers.team.url=...`로 세션에 주입. 팀장에게만 노출되는 도구(`hire`, `dismiss`, `delegate`)와 전원 도구(`report`, `ask_user`)를 나눈다.
  - `hire(name, role, engine?, instructions?)` — **팀장이 팀원을 생성.** 데몬이 CLI를 출근시키고(문으로 입장) `{memberId}` 반환. `instructions`는 그 팀원의 INSTRUCTIONS.md 초안이 되며 사용자가 앱에서 덮어쓸 수 있다. 상한: 팀당 동시 팀원 수(기본 4, 설정), 초과 시 `isError`. `engine`은 팀 설정의 허용 목록에서만.
  - `dismiss(memberId)` — **팀장이 팀원을 삭제.** 대상이 idle이고 미종료 task가 없을 때만 허용(아니면 `isError` — 먼저 interrupt하거나 보고를 기다리라고 안내). 사용자 "퇴근"은 이 제한 없이 강제(aborted 후처리).
  - **사용자 지시도 task다.** `member.instruct`는 `tasks(from='user', to=대상 멤버)` 행을 만들고 `[TASK#7 from user]\n<지시>` 형식으로 pty에 타이핑한다(v1a는 대상이 아무 멤버, M4부터는 팀장만). v1a에서는 `report` MCP가 없으므로 `Stop` 시점의 마지막 assistant 메시지(트랜스크립트에서 읽음)를 `report_text`로 저장해 내 책상 "보고"로 쓴다.
  - `delegate(to_member, task)` — 비동기. `tasks` 행 생성 후 즉시 `{taskId}` 반환. 대상이 idle이고 열린 질문이 없으면 `[TASK#12 from m1(팀장)]\n<task>`를 그 멤버 pty에 타이핑, 아니면 `queued` 후 조건 충족 시.
  - `report(taskId, summary, files?, status: done|blocked|aborted)` — taskId 필수. 상위에게의 전달은 버퍼링: **그 팀장이 발행한(delegate로 만든) task** 중 미종료가 0이 되는 순간(팀장이 사용자에게서 받은 task는 세지 않는다) `[REPORTS task#12 ...]\n...\n[ALL_REPORTS_IN]` 한 덩어리를 팀장 pty에 타이핑. `blocked`는 즉시 단독 전달. 최상위 report는 사용자에게(내 책상 "보고", `tasks.report_text`에 저장).
  - `ask_user(question, options?)` — 비블로킹. `pending(question)` 등록 후 `{questionId}` 즉시 반환, 도구 결과에 "답은 `[ANSWER q#N]` 메시지로 온다, 필요하면 턴을 끝내라" 포함. 답변은 pty에 `[ANSWER q#N]\n<answer>` 타이핑.
  - **직급 규칙은 데몬이 강제.** `hire/dismiss/delegate`는 팀장만, `report`는 팀원→팀장·팀장→사용자만, taskId는 자기 것만. 위반 시 `isError` + 사유, `error` 이벤트. v1 팀장 엔진은 Claude 고정(Codex MCP 주입 검증 후 해제).
- **팀 단위 셸 뮤텍스:** `PreToolUse`(Bash/PowerShell)에서 데몬이 락을 잡고, 아래 표의 어느 하나가 오면 해제한다. 락이 잡혀 있으면 두 번째 셸 도구의 `PreToolUse` 응답을 앞 명령이 끝날 때까지 보류(캐릭터 "대기 중" 말풍선).

  | 해제 조건 | 비고 |
  |---|---|
  | `PostToolUse`(성공·실패 모두) | 실패 시에도 `PostToolUse`가 오는지 needs verification; 안 오면 `Stop`으로 대체 |
  | `PermissionRequest` deny / 사용자 거부 | 명령이 실행되지 않음 |
  | 해당 멤버 `Stop` / interrupt / fire / error | 안전망 |
  | 보유 상한(예: 30분) 초과 | 경고 이벤트 + 강제 해제 |

  **보류 중 hook 타임아웃:** 두 번째 셸의 `PreToolUse`를 hook `timeout`(기본 60초로 알려짐, needs verification; 설정으로 늘릴 수 있음) 안에 못 풀면 데몬은 deny가 아니라 **pass-through(결정 없음)**를 돌려준다 — 명령을 포기시키는 것보다 뮤텍스가 한 번 뚫리는 게 낫다. 빌드처럼 오래 걸리는 앞 명령을 위해 timeout 상한을 Next Steps 0에서 실측하고, 상한이 낮으면 뮤텍스를 "경고만"으로 낮춘다. Codex는 hooks가 `PreToolUse` 상당을 제공하면 동일, 아니면 v1은 Codex 멤버를 읽기 위주 작업에 배정.
- **대기 정책:** 허가·질문 무기한 대기. 재접속 시 `pending(open)` 최우선 표시. hook 보류의 상한(타임아웃)이 있으면 그 직전에 데몬이 `deny`를 돌려주고 pending을 `expired`로 바꿔 내 책상에 "재지시 필요"를 띄운다(Next Steps 0에서 상한 확인).
- **interrupt / fire / error 공통 후처리:** 그 멤버의 `tasks(queued|assigned)` → `aborted` + 상위에 `[REPORTS ... status=aborted]` 즉시 전달, 열린 `pending` 전부 `expired`, 셸 락 해제. 팀장 fire 시 하위 task 전부 aborted + 팀원 interrupt. `error`(프로세스 비정상 종료)도 같은 후처리.
- **데몬 재시작 복구:** 기동 → working/waiting이던 멤버를 `claude --resume <session_id>` / `codex resume <id>`로 다시 띄우고 `[RESUMED] 데몬이 재시작됐다. 진행 중이던 작업: task#12 "<instruction>". 마지막 확인된 행동: <events 최근 5건>. 현재 상태를 점검하고 이어서 진행하라.`를 타이핑. `pending(approval)`은 hook 프로세스가 죽었으므로 `expired`. `pending(question)`은 출처별로: TeamTools `ask_user`(턴 종료 상태)는 유효, TUI `AskUserQuestion` 메뉴는 프로세스와 함께 사라지므로 `expired`. **전제 확인 필요:** 데몬이 죽을 때 ConPTY 자식이 살아남는지(needs verification). 살아남으면 진행 중 작업을 죽이지 않도록 "기동 시 PID 정리"를 "살아 있는 자식에 재-attach 시도, 실패 시에만 종료 후 `--resume`"으로 바꾼다(node-pty는 재-attach를 지원하지 않으므로 사실상 종료 후 resume; Next Steps 0에서 결정).
- **팀장 프롬프트 주입 방식:** 첫 사용자 메시지로 타이핑하면 compaction 후 유실될 수 있다. `--append-system-prompt`(대화형 모드에서 적용되는지 needs verification)를 우선하고, 안 되면 팀 cwd에 데몬이 `CLAUDE.md`/`AGENTS.md` 섹션을 쓰고 고용 해제 시 지운다.
- **델타·영속 분리:** `term` 바이트는 저장하지 않는다(seq 없음). 영속 `events`는 hook 단위(도구 호출 started/completed, 턴 시작/종료, pending 생성/응답). 보존: 팀당 최근 5만 건.
- **SQLite:** `teams`, `members(rank, engine, session_id, child_pid, cwd, status)`, `events(seq)`, `pending(id, member_id, type, payload, status: open|answered|expired)`, `tasks(id, from_member, to_member, instruction, status: queued|assigned|reported|aborted, report_text)`.

| thinking | `UserPromptSubmit` 이후 도구 호출 사이(파생) | 턴 시작 이후 도구 사이(파생) |

| editing | `PreToolUse` Edit/Write/NotebookEdit | apply_patch |
| running | `PreToolUse` Bash/PowerShell | 그 외 shell 명령 |
| waiting_approval | `PermissionRequest` | 승인 hook 또는 TUI 프롬프트 감지 |
| asking | `PreToolUse` AskUserQuestion, TeamTools `ask_user` | TeamTools `ask_user`, request_user_input 상당 |

**4. 팀·직급 모델**
- `Team{ id, name, cwd, leaderId, maxMembers, allowedEngines, members[] }`, `Member{ id, name, rank: leader|member, engine, sessionId, status, instructionsPath, hiredBy: user|leader }`.
- 직급 2단(팀장/팀원). 팀 생성 시 팀장이 자동 출근. **v1a(팀 기능 없음)는 사용자가 모든 멤버에게 직접 지시**, **M4부터 팀장에게만**(rank 검사). 팀원 직접 지시는 v2(단, 터미널 탭에서 직접 타이핑은 언제나 가능 — 그건 "지시"가 아니라 터미널 사용).
- **팀장 = 오케스트레이터.** 팀장 지시문 기본 템플릿에 들어가는 것: 사용자 명령을 받으면 작업을 쪼개고, 필요한 팀원이 없으면 `hire`(역할·엔진·초안 지시문 지정), 있으면 `delegate`, 끝난 팀원은 `dismiss`, 보고가 모이면 취합해 `report`. 규칙: "팀원마다 겹치지 않는 디렉토리 배정, 빌드·테스트는 한 번에 한 명, 팀원 상한 N".
- 흐름: 사용자→팀장 `[TASK#n from user]` → 팀장 (`hire`×K) → `delegate`×N → 팀원 pty에 `[TASK#..]` → 팀원 작업 → `report` → 버퍼링 → 팀장 pty에 `[REPORTS ...][ALL_REPORTS_IN]` → 팀장 취합 `report` → 내 책상 "보고" → (팀장이 유휴 팀원 `dismiss`).
- **사용자 개입:** 출근(팀원 추가)·퇴근(팀원 삭제)·지시문 편집은 언제든. 사용자가 출근시킨 팀원(`hiredBy=user`)은 팀장이 `dismiss`할 수 없다(퇴근은 사용자만). 팀원 구성이 바뀌면 데몬이 팀장 pty에 `[TEAM] 팀원 변경: +이음(Claude, 역할 …)` 알림을 타이핑한다.

## 직무 체계 rev 3 (2026-09-16, D-32) — "4. 팀·직급 모델"을 대체

```
사용자 ──부서 생성·부장 임명──▶ 부장(head) ──팀 생성·팀장 배치──▶ 팀장(lead) ──팀원 고용──▶ 팀원(member)
   ◀── 보고·ask_user (부장만) ──┘        ◀── 보고·ask_parent ──┘         ◀── 보고·ask_parent ──┘
```

- **부서(department)** = 프로젝트(cwd). `department.create{name, cwd, headEngine, headName}` → 부장 자동 출근. 사용자 지시는 부장에게만(`member.instruct` 대상 = 부장, 나머지는 -32004).
- **팀(team)** = 부서 안의 작업 단위. 부장이 `create_team(name, leadName, engine?, instructions?)`으로 만들고 팀장이 자동 출근. 같은 cwd, 팀장이 디렉토리를 나눠 맡긴다.
- **멤버 트리**: `members.parent_id`(부장은 null, 팀장은 부장, 팀원은 팀장), `rank ∈ {head, lead, member}`. 규칙 하나로: **고용(`hire`)·해고(`dismiss`)·위임(`delegate`)은 자기 직속 아래에게만, 보고(`report`)·질문(`ask_parent`)은 자기 직속 위에게만.** 부장의 `report`/`ask_user`만 사용자에게 간다.
- **도구(TeamTools MCP), 직급별 노출**:
  - 부장: `create_team`, `dismiss_team`, `delegate(to=팀장)`, `reply(to=팀장, text)`, `report`(→사용자), `ask_user`.
  - 팀장: `hire`, `dismiss`, `delegate(to=팀원)`, `reply(to=팀원, text)`, `report`(→부장), `ask_parent`(→부장).
  - 팀원: `report`(→팀장), `ask_parent`(→팀장).
  - `ask_parent`는 부모 pty에 `[QUESTION from X q#N]`으로 들어가고, 부모는 `reply`로 답하거나(자식 pty에 `[ANSWER q#N]`) 자기 상위에 다시 묻는다. 부장만 `ask_user`로 사용자에게 올린다 — 이것이 "진짜 중요한 문제"의 경로.
- **보고 버퍼링**은 부모 단위로 일반화: 자식들의 미종료 task가 0이 되면 `[REPORTS …][ALL_REPORTS_IN]` 한 덩어리. `blocked`는 즉시.
- **셸 허가**는 직급과 무관하게 사용자 카드로. 팀 단위 "이번 세션 항상 허가" 옵션 검토.
- **팀장은 팀원 없이 직접 일해도 된다.** 부장은 팀 없이 일하지 않는다(팀원 직접 고용 금지).
- **후처리**: 상위가 퇴근하면 그 하위 트리 전체가 정리된다(부장 퇴근 = 부서 전원). `waiting_reports`는 자식이 있는 모든 직급에 적용.
- **사무실 배치**(M6에서 확정): 부서 = 탭, 부장 책상 상단, 팀별 책상 클러스터, 내 책상은 부장 보고·질문·허가 카드만 받는다.
