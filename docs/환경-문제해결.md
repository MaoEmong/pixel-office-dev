# 환경·CLI 인증 문제 해결 (T57)

## 시작할 수 없을 때

앱은 새 데몬 시작 전에 package.json, Node.js 24 이상, SQLite,
tsx·node-pty·ws·qrcode·zod·xterm·MCP SDK 로딩을 확인한다.
확인된 설치 문제는 실패 화면에 복구 방법을 바로 표시한다. 환경을 고친 뒤 '다시 시도'를 누른다.
이미 실행 중인 데몬에 붙는 경우에는 새 시작 검사를 하지 않는다.

| 문제 | 처리·복구 |
|---|---|
| Node 실행 불가 | Node.js 24 이상 설치, 앱 재실행. 필요하면 PIXEL_NODE에 실행 파일 전체 경로 지정 |
| Node 24 미만 | 지원 버전으로 교체 후 재실행 |
| package.json 누락·손상 | 저장소 전체를 받고 dev/daemon 폴더 확인 |
| 의존성 누락 | dev/daemon에서 npm ci 후 다시 시도 |
| node-pty 로딩 실패 | Node·OS에 맞는 네이티브 모듈 설치 확인. npm 설치 로그에서 권한·빌드 실패 확인 |
| 검사 시간 초과 | Node 실행·보안 프로그램 차단 확인 후 재시도 |
| 포트 충돌·데이터 폴더 권한·DB 오류 | daemon.log의 실제 오류 확인. 다른 프로세스를 자동 종료하거나 DB를 자동 삭제하지 않음 |

새 설치로 열린 앱의 PATH에 경로가 없으면 앱을 다시 연다.
Windows 소스 빌드는 Flutter, Visual Studio C++ 데스크톱 개발 도구, 심볼릭 링크 권한이 별도로 필요하다.
이는 앱이 실행되기 전의 빌드 조건으로 런타임 검사 대상이 아니다.

## CLI 설치·로그인

앱 상단 ⋮ → '환경 점검 · CLI 로그인'에서 확인한다.
사용할 엔진만 설치하면 된다. Codex 미설치는 Claude 사용을 막지 않는다.
설치·로그인 변경 후 '다시 검사'를 누른다.

| 상태 | 행동 |
|---|---|
| 미설치 | 공식 CLI 설치, PATH 또는 PIXEL_CLAUDE_EXE/PIXEL_CODEX_EXE 확인, 앱 재실행 |
| 로그아웃 | 새 터미널에서 claude auth login 또는 codex login 실행 |
| 확인 불가 | 네트워크·권한·CLI 버전 확인. 로그아웃이라고 단정하지 않음 |
| 정상 | 상태 명령에서 인증 확인. 실제 모델 사용 가능·남은 한도를 보장하는 검사는 아님 |

사용자 RPC의 부서/팀/멤버 생성, 멤버 지시·재고용·재시작, workflow 대화·시작·재개는
관련 엔진의 미설치·로그아웃이 확인되면 실행 전에 거부한다. 상태 확인 불가만으로는 막지 않는다.
검사는 사용자 RPC 경로에 적용되며 내부 팀 도구·자동 세션 복구 전체를 대체하지 않는다.
진행 중 인증 만료·요금 한도·서버 오류는 CLI 터미널과 로그도 확인한다.
오류 뒤 요청을 반복하기 전 실제 실행 결과를 확인한다.

## 특정 프로젝트 멤버만 로그인 대기 중일 때

프로젝트 세션은 .pixel-office/sessions/<멤버 ID>/claude 또는 codex를 별도 홈으로 쓴다.
캐릭터를 선택한 뒤 환경 점검에서 '선택 멤버 검사'를 누른다.
기존 세션 홈에서 상태를 검사하고 로그아웃이면 정확한 홈을 지정한 로그인 명령을 보여준다.
새 터미널에서 안내된 명령을 실행한 뒤 다시 검사한다. 환경변수는 그 터미널에만 적용한다.
필요하면 해당 멤버를 재고용·재시작한다. 세션 폴더나 인증 파일은 삭제하지 않는다.

점검은 CLI 상태 명령만 사용한다. 비밀번호·토큰·이메일을 결과에 표시하지 않고,
라이브러리 자동 설치나 인증 정보 덮어쓰기를 수행하지 않는다.
