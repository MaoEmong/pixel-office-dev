# 작업 계획 — 태스크 분해

설계: [01-설계문서.md](01-설계문서.md) · 실측: [02-실측-체크리스트.md](02-실측-체크리스트.md) · 결정: [04-결정기록.md](04-결정기록.md)
이 파일이 **진행 상태의 단일 기준**이다. 태스크가 끝나면 여기 체크박스를 채우고 `worklog/`에 기록을 남긴다.

## 문서화 규칙 (모든 태스크 공통)

1. **태스크 하나 = worklog 하나.** `docs/worklog/T##-<slug>.md`, 템플릿은 [worklog/_template.md](worklog/_template.md). 내용: 목표 / 한 것 / 검증(명령·관찰 결과 그대로) / 발견한 함정 / 결정 / 남은 것.
2. **결정은 [04-결정기록.md](04-결정기록.md)에 append.** "왜 이렇게 했나"가 나중에 궁금해질 것만. 번호(D-##)·날짜·맥락·결정·대안·결과.
3. **설계문서는 고치지 않고 덧붙인다.** 설계와 달라지면 01의 해당 섹션을 수정하지 말고 04에 결정을 적고, 01 맨 아래 "설계 변경 이력"에 한 줄.
4. **코드 폴더마다 README.** `dev/daemon/README.md`, `dev/app/README.md`: 실행 방법·환경변수·포트·디렉토리 구조. 태스크가 구조를 바꾸면 같이 갱신.
5. **검증은 재현 가능하게.** "됐다"가 아니라 실행한 명령과 출력·스크린샷 경로. 스크린샷은 `docs/worklog/img/`(전체 화면 캡처 금지, 창 단위).
6. **완료 정의:** 코드 + 검증 증거 + worklog + 03 체크 + 커밋(영어 명령형, 태스크 단위). 이 다섯 개가 다 있어야 완료.

## 마일스톤 개요

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| M0 | 데몬 스파이크 (Claude만, 콘솔 클라이언트) | 콘솔에서 고용→지시→허가→재접속 replay |
| M1 | Flutter 사무실 최소 + 터미널 탭 | 캐릭터가 이벤트로 움직이고 터미널이 보임 |

| M3 | Codex 어댑터 | 혼합 팀에서 Codex 캐릭터가 동작 |
| M4 | 팀·오케스트레이터·TeamTools | 팀장이 hire/delegate/report, 출근/퇴근, 지시문 |

| M6 | 디자인 | 팀 위계·터미널 탭 반영 레이아웃, 스프라이트 |

## M0 — 데몬 스파이크 (`dev/daemon/`)

기술 결정(04 참고): TypeScript + Node 24, 실행은 `tsx`, DB는 **`node:sqlite`**(Node 24 내장, 네이티브 빌드 없음), WS는 `ws`, pty는 `node-pty`, 화면은 `@xterm/headless`.

- [ ] **T00 저장소·데몬 골격** — `git init`(루트), `.gitignore`(node_modules, build, sandbox, *.log, `%LOCALAPPDATA%` 계열 제외), `dev/daemon` 패키지 생성(tsx, typescript, node-pty, @xterm/headless, @xterm/addon-serialize, ws), `src/` 폴더 구조, `npm run dev`로 "daemon listening"까지. README 초안. → worklog T00
- [ ] **T01 PtyManager** — `spawnMember({engine:'claude', cwd, memberToken})`: env 정리(`CLAUDE_CODE*` 제거, `PIXEL_MEMBER` 주입), args(`--settings`, `--permission-mode default`, `--resume?`), `write/resize/kill`, `onData/onExit`. 세션 설정 파일 생성기(hooks → `node hook.js`). 검증: 스파이크와 동일한 왕복. → T01
- [ ] **T02 ScreenModel** — headless xterm 래퍼: `feed(bytes)`, `serialize()`, `lastLine()`, `isPromptReady()`(`? for shortcuts`/`shift+tab to cycle`), `detectDialog()`(온보딩 Enter / 폴더 신뢰 ↓+Enter / Codex 신뢰 Enter), 패턴은 `tui-maps/claude-2.1.json`으로 분리. 검증: 실측 로그의 화면 텍스트로 단위 테스트. → T02
- [ ] **T03 HookReceiver + hook.js** — HTTP `/hook/<memberToken>/<event>`, 페이로드 파싱, 결정이 필요한 이벤트는 promise로 보류(`pending`), 타임아웃 시 pass-through. `hook.js`는 stdin→POST→stdout 그대로(스파이크 `hookprobe.js` 정리). 검증: 스파이크 재현 + 보류 90초. → T03
- [ ] **T04 ClaudeHooks 어댑터** — hook 이벤트 → 오피스 이벤트(설계 표), `session_id` 갱신(모든 source), `PermissionRequest`/`AskUserQuestion` → `pending(approval|question)`, `SessionStart` → 멤버 INSTRUCTIONS.md를 `additionalContext`로, `PostToolUse|PostToolUseFailure` 처리, `Stop` → idle + `last_assistant_message`. 검증: 이벤트 로그가 표와 일치. → T04
- [ ] **T05 InputQueue** — 멤버별 큐, flush 조건(hook idle ∧ promptReady ∧ 사용자 직접 타이핑 3초 경과), bracketed paste, `instruct/type` 구분. 검증: 작업 중 지시 2개 넣고 순서·시점 확인. → T05
- [ ] **T06 Store** — `node:sqlite` 스키마(teams, members, events(seq), pending, tasks), `appendEvent`(전역 seq), `snapshot()`, `eventsQuery()`, 보존 정리. 검증: 재시작 후 seq 이어짐. → T06
- [ ] **T07 WS JSON-RPC 서버** — 토큰 파일(`%LOCALAPPDATA%\pixel-office\daemon.json`), `hello{since}`→`snapshot`+replay, v1a RPC(`team.create, member.clockIn/clockOut, member.instruct/type/attach/detach/resize/interrupt, approval.respond, question.respond, events.query, daemon.shutdown`), `event`/`term` 알림. 프로토콜 문서 `dev/daemon/PROTOCOL.md`. → T07
- [ ] **T08 콘솔 클라이언트** — `npm run cli`: 대화형 REPL(hire/instruct/approve/answer/attach/events). Flutter 없이 v1a 흐름 검증용, 이후에도 디버깅 도구. → T08
- [ ] **T09 재시작 복구** — 기동 시 working/waiting 멤버를 `--resume`으로 재스폰, `[RESUMED]` 메시지, approval pending `expired`, question pending 유지. 검증: 데몬 kill → 재기동 → 콘솔에서 이어서 대화. → T09
- [ ] **T10 M0 시연·정리** — 시나리오(고용 2명 → 지시 → 허가 → 질문 → 창 닫기(콘솔 종료) → 재접속 replay → 데몬 재시작 복구)를 worklog에 명령·출력으로 기록. hook `timeout` 상한(86400) 확인. → T10
