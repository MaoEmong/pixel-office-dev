# 작업 계획 — 태스크 분해

설계: [01-설계문서.md](01-설계문서.md) · 실측: [02-실측-체크리스트.md](02-실측-체크리스트.md) · 결정: [04-결정기록.md](04-결정기록.md)
이 파일이 **진행 상태의 단일 기준**이다. 태스크가 끝나면 여기 체크박스를 채우고 `worklog/`에 기록을 남긴다.

## 문서화 규칙 (모든 태스크 공통)

1. **태스크 하나 = worklog 하나.** `docs/worklog/T##-<slug>.md`, 템플릿은 [worklog/_template.md](worklog/_template.md). 내용: 목표 / 한 것 / 검증(명령·관찰 결과 그대로) / 발견한 함정 / 결정 / 남은 것.
2. **결정은 [04-결정기록.md](04-결정기록.md)에 append.** "왜 이렇게 했나"가 나중에 궁금해질 것만. 번호(D-##)·날짜·맥락·결정·대안·결과.
3. **설계문서는 고치지 않고 덧붙인다.** 설계와 달라지면 01의 해당 섹션을 수정하지 말고 04에 결정을 적고, 01 맨 아래 "설계 변경 이력"에 한 줄.
4. **코드 폴더마다 README.** `dev/daemon/README.md`, `dev/app/README.md`: 실행 방법·환경변수·포트·디렉토리 구조. 태스크가 구조를 바꾸면 같이 갱신.
5. **검증은 재현 가능하게.** "됐다"가 아니라 실행한 명령과 출력·스크린샷 경로. 스크린샷은 `docs/worklog/img/`(전체 화면 캡처 금지, 창 단위).
6. **완료 정의:** 코드 + 검증 증거 + worklog + 03 체크 + 커밋(영어 명령형, 태스크 단위). 이 다섯 개가 다 있어야 완료.
