## D-16 · 2026-09-15 · 세션 hooks `timeout`은 86400초, 만료 시 TUI 프롬프트가 폴백

## D-24 · 2026-09-16 · Codex 부팅 완료는 화면(prompt-ready)으로 판정, SessionStart는 첫 프롬프트 때 온다
- 맥락(T20): Codex hooks의 `SessionStart`는 부팅 시가 아니라 **첫 프롬프트 제출 시** 발화. hook만 기다리면 멤버가 영원히 `starting`이라 첫 지시가 안 들어감.
- 결정: Codex 멤버는 `Office.watchBootReady()`가 ScreenModel prompt-ready(다이얼로그 없음, `model: loading` 아님)를 보고 `starting → idle`로 올린다. SessionStart가 먼저 오면 그걸로.
- 참고: node-pty는 PATH의 `codex` 셸 shim(.cmd/.ps1)을 못 띄움 → `config.codexExe`는 실제 `codex.exe` 경로여야 함(T22에서 npm 전역 경로 자동 탐색).

## D-25 · 2026-09-16 · 턴 종료 hook 이 없으면 화면으로 idle 을 판정한다(`idle{summary:'screen-idle'}`)
- 맥락(T23 함정 1): Codex 사용량 한도 안내는 화면에만 찍히고 `Stop` hook 이 오지 않는다. 데몬은 `UserPromptSubmit` 으로 올려 둔 `working` 을 내려 줄 근거가 없어 멤버가 퇴근할 때까지 `working` 에 갇힌다 — ① 사무실 표시가 틀리고 ② `InputQueue.isIdle` 게이트가 안 열려 다음 지시가 큐에 머문다. 원인은 한도가 아니라 "턴 종료 hook 없이 프롬프트로 돌아오는 화면" 일반이고, Claude 도 턴이 이상하게 끊기면 같은 일이 난다.
- 결정: `Office.watchScreenIdle()` — 엔진 공통, 멤버당 타이머 하나, 500ms 폴링(`watchBootReady`/`watchInterrupted` 와 같은 모양). status 가 `working`/`waiting_approval`/`waiting_answer` 이고, **열린 pending 이 하나도 없고**, 화면에 다이얼로그·busy 표시가 없고 prompt ready 이고, 그 사이 새 hook 이 도착하지 않은 상태가 **3초 연속**이면 `idle{summary:'screen-idle'}` + status `idle`. 조건이 하나라도 깨지면 창을 닫고 처음부터 다시 잰다. 세션이 끝나면 타이머를 멈춘다.
- 버린 대안: ① 엔진별(Codex 전용) 폴백 — 원인이 엔진이 아니라 화면이다. ② status 만 바꾸고 이벤트는 안 남기기 — 앱 로그에서 "왜 내려왔나"를 설명할 수 없다. ③ 창을 더 짧게(1초) — 화면이 잠깐 준비로 보이는 구간(도구 출력 사이)에서 오발화 위험.
- 근거: worklog/T23b-defects.md, `test/office/ScreenWatch.test.ts`(실측 픽스처 `codex/usage-limit.txt` · Claude 준비 화면). 보류·busy·다이얼로그 중에는 발화하지 않는 것을 테스트로 고정.

## D-26 · 2026-09-16 · `approval-prompt` 은 "통과" 가 아니라 "막힘" 이다 — `dialogPassed` 대신 `blocked`+`dialogBlocked`
- 맥락(T23 함정 2, T21 후속): Claude 2.1.270 은 `PermissionRequest` hook 을 보류하는 동안에도 자기 TUI 허가 프롬프트를 띄운다. ScreenModel 은 이걸 `approval-prompt` 로 감지하고 D-23 대로 `suggestedKeys: []` 를 준다(키 안 나감 = 안전). 그런데 InputQueue 가 빈 키 시퀀스를 "보냈다" 치고 `dialogPassed` 를 emit 해 `daemon.notice` 에 `passed first-run dialog (approval-prompt)` 가 허가 대기 내내 2초마다 찍혔다(실기 7회).
- 결정: InputQueue 는 `suggestedKeys` 가 비어 있으면 키를 보내지 않고 `dialogPassed` 도 내지 않는다. 대신 ① `blocked('dialog')`(다른 blocked 이유와 같은 5초 계량, 큐에 기다리는 항목이 있을 때만) ② 새 이벤트 `dialogBlocked(kind)` — **그 다이얼로그가 사라질 때까지 kind 당 한 번**. ## D-33 · 2026-09-16 · 트리 스키마의 소유 관계: task·event·셸 락은 **부서** 소유, 부장은 팀에 속하지 않는다
- 맥락: T34(D-32 구현)에서 스키마를 v2로 올리며 "팀" 을 가정하던 세 곳이 걸렸다 — ① 부장은 어느 팀에도 속하지 않는데 `members.team_id` 가 NOT NULL, ② 사용자 task 는 팀 없는 부장이 받는데 `tasks.team_id` 가 팀 FK, ③ 셸 락이 팀 단위인데 D-32에서 **한 부서의 팀들이 같은 cwd** 를 쓰기로 했다.
- 결정:
  1. `members.team_id` 를 **nullable** 로. 부장은 `team_id null`(부서 직속), 팀장·팀원만 팀에 속한다. 클라이언트도 `Member.teamId: string | null`.
  2. `tasks.team_id` → **`department_id`**(부서 FK, cascade). 부작용으로 `team.delete` 가 더는 보고 이력을 지우지 않는다 — T29 결함 ⑤("`team delete` 가 tasks 행을 지움")가 여기서 해소됐다(T36 몫이었지만 스키마가 먼저 정리됨).
  3. `events` 는 `department_id` 를 **추가**하고 `team_id` 는 남긴다(팀 없는 부장은 `''`). 이력 테이블이라 재작성 비용이 크고, 팀 단위 조회도 아직 쓸 데가 있다.
  4. **셸 락 범위 = 부서**(`ShellMutex` 키를 `teams.id` → `departments.id`). 같은 cwd 에서 두 팀이 동시에 빌드하면 막아야 한다.
  5. `members.hired_by` 값은 `'user' | 'leader'` 그대로 둔다. 의미만 "사용자 / 상위 멤버" 로 읽는다 — 행 마이그레이션과 앱 문자열을 아끼는 쪽.
- 버린 대안: 부장용 더미 팀을 만들어 `team_id` NOT NULL 유지(트리를 거짓말하게 만든다), `events` 통째 재작성(414행 개발 DB에 비해 과함), `hired_by` 값 `'parent'` 로 변경(이득 없는 churn).
- 결과: v1 DB 한 개(개발 머신)는 `Store.migrate()` 가 열 때 한 번에 옮긴다 — 팀 하나 = 부서 하나, 그 팀장이 부장이 되고 옛 팀은 그 부서의 팀으로 남는다(부장이 레거시 팀의 팀장을 겸한다). 실측: 기동 시 v1(events 414행) → v2 정상 이전, `test/store/Migration.test.ts` 4건.

## D-34 · 2026-09-16 · 없어진 사용자 기능은 지우지 않고 `force:true` 뒤로 숨긴다
- 맥락: D-32로 "사용자가 팀·팀원을 직접 만드는 기능" 이 사라졌다. 그런데 콘솔·테스트·망가진 트리 복구에는 그 길이 여전히 필요하다.
- 결정: `team.create` 와 `member.clockIn` 은 RPC 로 남기되 **`force:true` 가 없으면 -32004**. 앱은 절대 보내지 않고, 콘솔(`team create`, `hire`)만 붙여 보낸다. `member.clockOut` 은 **누구에게나 그대로 허용** — 굳은 세션을 사용자가 치울 비상구가 없으면 안 된다(문서에 "비상구" 로 명시).
- 결정(부수): `member.clockIn` 에 `parentId` 를 주면 정식 고용 경로와 **같은 직급 사슬 검사**를 받고, 주지 않으면 부서·팀에 바로 꽂는다(부모 자동 결정, 없으면 부모 없는 행). 사슬 강제는 `Office.hireChild` 한 곳에만 둔다.
- 버린 대안: 메서드 삭제(콘솔·테스트가 통째로 막힌다), 별도 `debug.*` 네임스페이스(메서드 표가 두 벌이 된다).
- 결과: 앱(T37)은 `department.create` + 퇴근/중단/재시작만 쓰면 된다. 콘솔은 `dept create` 가 기본 길이고 `team create`/`hire` 는 디버그로 표시.
