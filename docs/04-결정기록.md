## D-11 · 2026-09-14 · hook 보류 타임아웃은 deny가 아니라 pass-through(`{}`)
- 맥락: HookReceiver(T03)가 결정을 24시간까지 보류. 상한을 넘기면 어떻게 답할지.

- 근거: 설계문서 "보류 중 hook 타임아웃" 항목. 어댑터(T04)가 필요하면 더 짧은 자체 타이머로 deny를 얹을 수 있음.

## D-12 · 2026-09-14 · node-pty ConPTY 자연 종료 시 내부 리소스를 직접 해제
- 맥락: T01 통합 테스트에서 `/exit`로 자식이 끝나도 node-pty 1.1.0(win32)이 conout 워커 스레드·pseudoconsole 핸들을 풀지 않아 데몬 프로세스가 종료되지 않음. `proc.kill()`로 우회하면 `conpty_console_list_agent`가 포크되어 stderr 스택과 5초 대기.
- 결정: `onExit`에서 `releaseConptyResources(proc)`로 내부 필드 3개를 직접 해제, 필드 형태가 바뀌면 `proc.kill()` 폴백. node-pty 업그레이드 시 재확인 항목.
- 근거: worklog/T01-PtyManager.md.

## D-14 · 2026-09-14 · SessionEnd reason `clear`·`resume`은 프로세스 종료가 아니다
- 맥락: 터미널 탭에서 `/clear`·`/resume`을 치면 같은 프로세스 안에서 `SessionEnd`→`SessionStart`가 온다.
- 결정: 어댑터(T04)는 이 두 reason을 비종료로 취급하고 상태를 바꾸지 않는다. 실제 종료는 pty `exit`(→ `onSessionExit`)로만 판정.

## D-15 · 2026-09-14 · hook 보류가 결정 없이 끝나면 `error` 이벤트 + "재지시 필요"
- 맥락: D-11의 pass-through 후 사용자에게 무슨 일이 있었는지 보여야 함.
- 결정: `hold-timeout`/`hold-closed` 시 pending을 expired로 바꾸고 `error{summary, pendingId}` 이벤트를 남긴다. 상태는 `working`(CLI가 자기 TUI 프롬프트를 쥔 상태).

## D-16 · 2026-09-15 · 세션 hooks `timeout`은 86400초, 만료 시 TUI 프롬프트가 폴백
- 맥락: T07 콘솔 검증 중 허가를 10분 넘게 방치하자 Claude가 hook(`timeout: 600`)을 끊음 → `hook connection closed before answer` error 이벤트 → pending 만료 → CLI 자체 TUI 허가 프롬프트 표시(D-11 pass-through 동작 확인). `type 하루 1`로 TUI에서 승인해 정상 완료.
- 결정: hook `timeout`을 설정값(`config.hookTimeoutSec`, 기본 86400)으로 올린다. 그래도 만료되면 "재지시 필요" 카드 + 터미널 탭에서 직접 답하는 것이 공식 폴백. 86400이 실제로 받아들여지는지는 T10에서 10분 이상 보류로 확인.
