# T67 — 작업 중 대화와 기존 오류 안내

## 확인한 원인

- 하단 입력, 대화 창, 서버의 대화 처리 모두 회의·실행·중단·검수 단계에서 메시지를 막고 있었다. 하단 입력은 이유를 알리지 않고 반환했다.
- 오류 팝업은 새 알림만 구독해서 앱 재실행 전에 발생한 중단을 놓쳤다. 색상 범례는 상태 설명이며 실제 오류 건수가 아니다.
- 현재 회의에는 삭제된 옛 참석자도 남아 있어 단순 재고용으로 복구할 수 없다.

## 수정

- 모든 진행 단계에서 부장에게 질문·변경 지시를 보낼 수 있다. 기존 계획, 회의 의견, 업무 배정, 중단 사유는 유지한다.
- 부장이 응답 중이면 현재 응답이 끝난 뒤 전달한다. 메시지 접수를 표시하고, 추가 대화 답변도 대화 기록과 답변 완료 표시에 반영한다.
- 추가 대화 답변으로 전체 작업이 완료되지 않도록 자동 완료와 직접 보고 양쪽을 막는다. 다음 업무 응답에서는 정상 보고할 수 있다.
- 하단 ‘작업 취소’는 진행 중인 흐름을 취소한다. 일반 지시 모드의 ‘중단’은 기존 동작을 유지한다.
- 처음 연결할 때 받은 상태, 다시 연결할 때 받은 상태, 저장된 작업 조회에서도 기존 오류를 팝업으로 알린다. 같은 오류는 반복해서 띄우지 않으며, 실제 복구 후 재발하면 다시 알린다.
- 해결되지 않은 작업 중단·AI 실행 오류는 하단에 건수와 원인을 남긴다. 눌러 팝업을 다시 열 수 있다. 실제 상태가 복구되면 경고가 사라진다.
- 삭제된 회의 참석자는 복구를 일부 진행하기 전에 확인하고, 복구 불가 이유와 취소 후 새 회의를 시작하는 방법을 알린다.
- 자동 상태 조회는 작업 관리 프로그램에 연결된 뒤 시작해 정상 시작 과정의 불필요한 연결 오류 팝업을 막는다.

## 확인

- 수정 전 재현 검사: 진행 단계별 서버 검사 4건과 하단 입력 검사가 실제 차단 때문에 실패함을 확인했다.
- 실제 입력 대기열·작업 기록·응답 처리를 연결한 검사로 바쁜 부장에게 메시지가 대기하고, 이후 전달되며, 답변과 중복 종료 알림이 작업 완료를 만들지 않음을 확인했다.
- 대화 창과 하단 입력에서 회의·실행·중단·검수 중 메시지 전송, 초기 오류 팝업, 재연결 중복 방지, 지속 경고, 복구 시 해제, 삭제된 참석자 안내를 검사했다.
- 서버: 타입 검사 통과, 전체 1,245건 통과·15건 건너뜀.
- 앱: 코드 검사 문제 없음, 전체 818건 통과·1건 건너뜀.
- Windows 실행 파일 생성 후, 실행 중인 응답·승인 대기가 없는 것을 확인하고 반영했다. 실제 사용자 업무에 새 지시나 회의 재개 요청을 테스트로 보내지 않았다.
- 현재 회의의 중단 자체를 자동 해제하거나 기록을 초기화하지 않았다. 기존 회의 복구와 새로운 작업의 실제 완료까지 검증했다는 의미는 아니다.
