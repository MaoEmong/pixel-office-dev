# T65 — 공통 오류 팝업과 부장 답변 상태

- 날짜: 2026-10-16

## 원인

부서 생성 외에도 실패를 작은 글씨나 잠깐 나타나는 알림으로만 표시하는 기능이 있었다.
단축키 승인, 작업 화면 입력·크기 변경은 실패를 아예 무시했다.
부장과의 대화는 요청 전송 처리와 최종 답변을 구분하는 표시가 없어 완료 여부를 알기 어려웠다.

## 확인과 변경

| 확인한 기능 | 기존 실패 처리 | 변경 |
|---|---|---|
| 대화·지시 전송, 중단, 회의 시작·재개·검수 | 창 내부 글씨나 작은 오류 표시 | 원인과 재시도 안내 팝업 |
| 승인·질문 응답 | 카드 내부 표시, 단축키는 실패 무시 | 공통 팝업 |
| 작업 화면 연결·입력·크기 변경 | 연결 실패 문구, 입력·크기 변경은 실패 무시 | 공통 팝업 |
| 부서 삭제·설정, 퇴근·재출근, 지시문 저장 | 작은 알림이나 창 내부 글씨 | 공통 팝업 |
| AI 선택·동시 작업 설정, 기록 조회·백업 | 창 내부 오류 표시 | 공통 팝업 |
| 기기 등록·승인·해제·접속 설정 | 창 내부 오류 표시 | 공통 팝업, 원격 서비스 시작 실패도 알림 |
| 복사·폴더 선택 | 일부 실패는 처리 누락 | 복사 실패 보고와 폴더 선택 오류 팝업 |
| 앱 화면 설정 읽기·저장 | 읽기는 기본값으로 넘어감, 저장은 배너 | 읽기 실패 콜백 및 팝업, 저장 실패도 팝업 |
| AI 작업 오류·실행 차단 사유 | 기록·배너·회의 창 내부 문구 | 오류 이벤트와 작업 중단 알림도 팝업 |

`RpcClient.call`은 실패를 호출자에게 그대로 전달하면서 별도 오류 알림도 보낸다.
`ActionErrorPopups`는 앱 전체에서 오류를 받아 기존 팝업을 순서대로 띄운다.
동일 원인으로 동시에 발생한 실패는 합치며, 자동 상태 조회의 동일 오류는 확인 후 반복해서 띄우지 않는다.
정상 조회가 확인되면 이후 발생한 오류는 다시 알린다. 사용자 재시도 실패는 계속 안내한다.
연결 확인과 종료 후 화면 정리 요청은 기존 연결 안내·종료 화면에서 처리하며,
부서 생성은 이미 자체 팝업이 있어 중복 팝업을 만들지 않는다.
요청 본문이나 인증 정보를 오류 알림에 추가로 저장하지 않는다.

## 답변 상태

- 대화 창 상단과 메인 화면 하단에 답변 준비·답변 중·승인 대기·질문 확인 대기·답변 완료·중단·연결 끊김을 표시한다.
- 부장 최종 메시지가 기록되고 작업 중 상태가 끝났을 때 완료로 표시한다. 단순 대기 상태만으로 완료라고 판단하지 않는다.
- 각 최종 답변에도 완료 표시를 붙인다. 새 질문을 보내면 최신 답변 상태를 다시 계산한다.
- 대화 창을 다시 열 때도 저장된 대화와 현재 연결·멤버 상태를 사용한다.
