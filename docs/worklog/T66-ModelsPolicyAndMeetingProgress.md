# T66 — Codex 모델 확인·AI 사용 설정·회의 진행 표시

- 날짜: 2026-10-16

## 확인한 원인

- 현재 저장된 AI 사용 설정은 Claude Code + Codex였다. 사용자가 두 AI를 모두 사용하겠다고 확인했다.
- Codex는 프로젝트 전용 설정에 복사된 모델을 그대로 읽었다. 화면에서 오류가 난 모델은 설치된 CLI가 현재 계정에 제공한 모델 목록에 없었다.
- 모델 요청이 거절돼도 CLI 자체가 종료되지 않아, 화면은 입력 대기 상태를 ‘한가함’으로 표시할 수 있었다.
- 회의의 의견 제출은 일반 업무 task와 별도라 기존 업무 상태만으로는 회의 참여 상태를 설명하지 못했다.
- 사용 AI 범위는 서버가 검사했지만 부장의 사용자 지정 지시문에 항상 명시되지 않았고, 메인 화면에서도 선택 범위를 확인하기 어려웠다.

## 변경

- 설치된 Codex의 `app-server` → `model/list`로 계정에서 제공되는 모델을 확인한다. 모델 작업은 실행하지 않는다.
- 기존 선호 모델이 목록에 있으면 유지하고, 없으면 계정 기본 모델을 실행 인자로 지정한다. 전역·프로젝트의 원본 설정 파일은 고치지 않는다.
- 목록을 확인하지 못하면 모델을 임의로 추정해 시작하지 않으며, 다음 시도에서 다시 확인한다. 동시 팀 생성은 확인 요청 하나를 공유한다.
- 화면에 표시된 지원 불가 모델 API 오류를 감지하면 멤버 오류와 구체적인 회의 중단 사유로 저장하고 팝업으로 알린다.
- AI 사용 범위를 세션 공통 안내와 회의 전달 내용에 포함한다. 사용자 지정 지시문이 있어도 적용된다.
- 메인 화면에서 선택한 AI 범위를 표시하고 바로 설정을 열 수 있다. 설정 변경 후 화면을 갱신하며 기존 AI와 설정이 다르면 안내한다.
- AI를 하나만 선택했다면 새 부서의 부장도 해당 AI를 기본값으로 사용하며, 설정 밖 AI 선택은 비활성화한다.
- 회의 안건, 현재 차례, 의견 제출 인원, 참가자별 상태, 최근 제출된 의견을 대화 창과 메인 화면에 표시한다.
- 사무실 책상과 멤버 패널에서 회의 참가자를 ‘의견 작성·제출 대기·제출 완료·부장 결정 대기·중단’으로 표시한다. 실제 오류·퇴근 상태는 가리지 않는다.
- 중단된 회의의 실패 참가자를 재고용한 뒤 같은 회의를 재개하는 명시적 버튼을 제공한다. 새 회의를 만들거나 기존 의견을 지우지 않는다.

## 검증 범위

- 실제 설치된 Codex에 모델 목록을 조회해, 문제가 난 모델이 목록에 없고 사용할 기본 모델이 제공됨을 확인했다. 인증 정보나 요청 본문은 출력하지 않았다.
- 모델 선택·조회 실패 후 재시도·동시 조회·지원 불가 화면 감지·CLI 실행 인자·AI 범위 지시문을 자동 검사한다.
- Claude 전용·Codex 전용·두 AI 사용 구분, 회의 진행 갱신, 책상 상태, 의견 표시, 실패 참석자 복구 순서를 자동 검사한다.
- 실제 사용자 프로젝트의 새 업무나 회의 발언은 검증을 위해 실행하지 않는다. 회의 재개는 사용자가 복구 버튼을 눌러 시작한다.

- 메인 화면에서 두 AI 사용 설정, 기존 회의 안건, 중단 사유와 실패 참석자 상태가 표시됨을 창 단위 캡처로 확인했다: [T66-main-progress.png](img/T66-main-progress.png).
- 기존 부서·회의·의견 기록은 유지했다. 참석자 복구와 회의 재개는 자동 실행하지 않았다.
