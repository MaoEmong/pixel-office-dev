## 목표

T40 이 실기에서 적어 두고 "디자인 판단이 필요하다"며 넘긴 패널 편차 넷을 고른 대로 **정하고** 고친다.
끝나면 ① 허가 카드 첫 줄이 어느 폭에서도 한 줄이고(낱말 중간에서 안 끊긴다) ③ 셸 대상이 따옴표·괄호를
달고 나오지 않으며 ② 인박스 "+N" 줄과 `ask_parent` 안내 카드가 접힘선 아래로 밀리지 않고 ④ 보고 본문이
긴 문단 하나여도 6줄만 차지한다. 덤으로 전체 suite 4판 중 1판꼴로 깜빡이던 `panel_width_test` 의
**진짜 원인**을 찾아 못으로 박는다.

## 한 것

### ① 허가 카드 첫 줄 = 한 줄 (`approval_summary.dart` · `pending_card.dart`, 커밋 `106058b`)

**증상**: 패널 480 에서 `❗ Write · t40-a.txt 쓰` / `기` — 낱말 중간에서 접혔다.

**원인은 폭이 아니라 배분이었다.** 첫 줄 Row 가 `Flexible(제목) + Spacer() + 메타` 였다. Row 는 비-flex 인
메타를 먼저 놓고 **남은 폭을 제목(flex 1)과 Spacer(flex 1)가 반씩** 나눠 가진다 — 제목이 실제로 쓸 수 있는
폭이 절반(480 에서 ≈146px)뿐이라 25칸짜리 첫 줄이 두 줄이 됐다.

**정한 것(디자인 판단)**: 첫 줄은 **언제나 한 줄**. 모자라면 줄이는 순서는
**대상(가운데 말줄임) → 도구 이름 → 동사는 절대 안 줄인다**. "쓰기/삭제/푸시" 가 잘리면 카드가 쓸모없다.
대상은 **가운데**를 줄여 확장자를 남긴다(`t40-abcdefgh.txt` → `t40-…txt`) — 앞만 남기면 무슨 파일인지 모른다.

- 구조: `Expanded(제목, maxLines: 1, ellipsis) + (위험 태그) + 메타`. `Spacer` 삭제.
- 규칙(순수 함수): `displayColumns`(한글·이모지 2칸의 반각 칸) · `middleEllipsis` ·
  `approvalHeadlineTextWidth(panelWidth, danger:)` · `approvalHeadlineColumns(px)` ·
  `fitApprovalHeadlineToColumns/ToWidth` · `fitApprovalHeadline(panelWidth:)`.
  예산 = 패널 폭 − 카드 여백/테두리/패딩(39) − 메타(160) − 위험 태그(46, 있을 때), 한 칸 7px, 하한 14칸.
- 카드는 `_CardFrame` 을 감싼 `LayoutBuilder` 로 **제 폭(≈ 패널 폭)** 을 받아 `fitTitle` 을 부른다.
  `_CardFrame.title`(그대로 쓰는 문자열)은 남겨 질문·`ask_parent` 카드는 건드리지 않았다.

### ③ 셸 대상의 따옴표·괄호 (`approval_summary.dart`, 커밋 `8b3603b`)

**증상**: `❗ PowerShell · t40-a.txt") 실행`. `commandTarget` 이 공백으로만 토큰을 끊고 마지막 조각을 그대로 썼다.

- `shellTokens(command)` — **따옴표를 아는** 쪼개기. 따옴표 안 공백은 한 토큰(`cat "a b.txt"` → `a b.txt`),
  따옴표 자체는 떨군다. 토큰 가운데 낀 따옴표도 떨어져 `…ReadAllBytes("D:\x\a.txt")` 가 깔끔해진다.
- `stripTargetWrappers(s)` — 감싼 `([{<"'` 와 꼬리 `)]}>"',;:!?` 를 벗긴다(토큰과 마지막 조각 양쪽에).
  확장자의 점·숨김 파일 앞 점은 안 건드린다.
- 회귀 표: PowerShell `[System.IO.File]::ReadAllBytes("…\t40-a.txt")` → `t40-a.txt` /
  bash `cat "a b.txt" | head` → `a b.txt` / `Set-Content -Path 'x.txt'` → `x.txt` /
  `git push origin main` → 대상 없음(`❗ Bash · 푸시`) / `rm -rf build/` → `build`.

### ② 인박스가 제 높이 안에서 스크롤 (`inbox.dart` · `right_panel.dart`, 커밋 `b5cfe0b`)

**증상**: 1280×720 에서 "+N" 접힌 줄과 `ask_parent` 안내 카드가 55% 접힘선 아래로 밀려 스크롤해야 보였다.
"+N" 은 **카드보다 먼저 보여야 하는 정보**다(대기가 더 있다는 사실).

- `PendingInbox` 가 블록 전체를 맡는다: **헤더 고정 / 카드 + `belowCards` 만 스크롤 / "+N"·"접기" 고정**.
  스크롤 영역은 `Flexible`(loose) 이라 블록 높이가 `min(패널 높이 × 55%, 내용)` 이 되고, 6px 팔레트
  스크롤바를 상시 보여 준다(`inbox.scroll` 키).
- 높이 상한이 있는지는 **Column 바깥의 `LayoutBuilder`** 로 본다 — Column 은 자식에게 세로 무한 제약을 주므로
  안쪽에서는 알 수 없다. 상한이 없으면(바깥이 스크롤을 주는 기존 호출·테스트) 예전처럼 그냥 쌓는다.
- `RightPanel` 은 `RecoveryHint` + `PendingCards`(ask_parent 안내)를 `belowCards` 로 넘기고 바깥
  `SingleChildScrollView` 를 걷어냈다. 안내 카드는 **스크롤 영역 끝**에 있어 스크롤로 닿는다(사양이 허용한 두 길 중 하나).

### ④ 보고 본문 클램프 = 표시 줄 (`report_tab.dart`, 커밋 `7878c0e`)

**증상**: 6줄 클램프가 **원문 줄** 기준이라 줄바꿈 없는 긴 문단 하나가 화면을 다 채웠다(캡처 10 ≈11줄).
사양(패스 4 ①)은 "6줄"만 적고 어느 줄인지 안 정했다 — **그려지는 줄**로 정한다.

- `clampReportBody(body, width:, maxLines: 6)` — `TextPainter(maxLines: 6)` 로 재고 넘치면 **마지막 표시 줄
  끝의 글자 위치**로 자른다. 자른 자리가 원문 오프셋이라 `splitReportBody` 가 그대로 이어서 쓰고(고정폭 덩어리
  판정 유지), 카드에 남는 **글자 자체가** 잘린다 — 클리핑만 하면 숨긴 글이 찾기·복사·읽어 주기에 그대로 남는다.
- 재는 글자는 가변폭 하나(`reportBodyTextStyle`)로 통일한다. 고정폭 줄은 더 낮으니 결과는 6줄 이하로 안전하다.
- 클램프 여부는 `LayoutBuilder` 로 받은 실제 본문 폭으로 판단한다.

### ⑤ `panel_width_test` "member.resize" 깜빡임 (`terminal_cache.dart` · `terminal_tab.dart`, 커밋 `408d8c7`)

**진짜 원인은 타임아웃이 아니라 놓친 이벤트였다.**

`daemon.countOf('member.attach') == 1` 은 요청이 **도착한** 순간 참이 된다. 그 뒤 응답이 돌아와야
`CachedTerminal.attached` 가 켜지는데, 그 틈에 폭이 480 → 660 으로 바뀌면 `onResize` 가 "아직 attach 전"이라
버려진다. **xterm 은 같은 크기로는 `onResize` 를 다시 부르지 않으므로** 그 한 번을 놓치면 데몬은 옛 크기를
영영 믿고, 테스트는 20초를 기다리다 죽는다. 단독 실행은 응답이 빨라 이 틈이 거의 안 벌어지고, suite 전체를
돌리면 벌어진다 — "4판 중 1판" 의 정체.

**이건 테스트만의 문제가 아니다.** 실제 앱에서도 터미널 탭을 열자마자 패널이 660 으로 벌어지는 그 순간이
같은 틈이라, 운이 나쁘면 CLI 가 480 폭 기준으로 줄을 접은 채 남는다.

- `CachedTerminal.sentCols/sentRows` — **데몬이 아는 크기**를 기억한다.
- `TerminalCache.syncSize(entry)` — 뷰 크기가 아는 크기와 다를 때만 `member.resize`. `onResize` 는 이 한 길로만
  나가고, 크기는 이벤트 인자 대신 터미널에서 다시 읽어 attach 와 **같은 clamp**(20~500 × 5~300)를 태운다.
- `markAttached(entry, cols:, rows:)` — attach 응답이 오면 알린 크기를 적고 **곧바로 한 번 더 맞춘다**.
  그 사이 넓어졌으면 여기서 resize 가 나간다. `markDetached` 는 아는 크기도 잊는다(재attach 때 새로 알린다).
- 테스트: attach 핸들러를 `Completer` 게이트로 붙잡아 **응답 전에 폭을 넓히는 순서를 강제**하는 회귀 1건.
  기존 resize 테스트는 요청이 아니라 `attached`(응답)까지 기다리게 바꿔 순서를 고정했다.

## 발견한 함정

1. **Row 의 `Flexible` + `Spacer` 는 남은 폭을 반씩 가른다.** `Spacer` 는 `Expanded(flex: 1)` 이라
   같은 flex 의 `Flexible` 과 경쟁한다. "왼쪽은 최대한, 오른쪽은 끝에" 를 원하면 **왼쪽을 `Expanded` 로 두고
   `Spacer` 를 빼야** 한다. 이번 ① 의 진짜 원인이고, 글자 수를 세는 쪽만 보면 영영 못 찾는다.
2. **Column 안에서는 "내 높이가 정해져 있는지" 를 알 수 없다.** Column 은 자식에게 세로 무한 제약을 준다 —
   `LayoutBuilder` 를 Column **바깥**에 둬야 `hasBoundedHeight` 가 참말을 한다. 안에 두면 언제나 무한이라
   `Flexible` 을 쓸지 말지 판단할 수 없다(무한 제약에 `Flexible` 을 쓰면 그 자리에서 예외).
3. **`SelectableText` 는 준 폭보다 좁게 접는다.** 커서 자리를 남기기 때문. 실측(테스트 서체, 폭 456)으로
   8px 넘게 좁았다 — `TextPainter` 로 6줄이라고 잰 글이 화면에서는 7줄이 됐다. 재는 쪽에서
   `reportBodyCaretGutter`(24) 를 빼고 재야 잰 줄과 그려진 줄이 같다. 같은 함정이 `TextField` 계열 전부에 있다.
4. **xterm `onResize` 는 "바뀔 때 한 번" 이다.** 그 한 번을 조건문으로 버리면(우리 경우 `attached` 가 아직
   false) 같은 크기로는 다시 오지 않는다. 이벤트를 버릴 거면 **버렸다는 사실을 기억**하거나(우리는 "데몬이 아는
   크기" 를 기억하는 쪽을 골랐다) 나중에 상태로 다시 맞춰야 한다.
5. **가짜 데몬의 `countOf(method)` 는 "요청 도착" 이지 "응답 처리" 가 아니다.** 여기에 걸어 두고 다음 단계로
   넘어가는 테스트는 부하가 걸리면 깜빡인다. 클라이언트 쪽 상태(여기서는 `CachedTerminal.attached`)로 기다려야
   순서가 고정된다. `panel_width_test` 말고도 같은 모양이 있는지 볼 만하다.
6. **테스트 서체는 글자마다 정사각형**이라 한글·ASCII 폭이 같다. 픽셀로 재서 무언가를 자르는 위젯 로직은
   테스트에서 실제와 다르게 동작한다 — ① 의 예산을 **패널 폭**에서 뽑은 이유다(카드 안에서 실제로 남은 px 로
   뽑았다면 테스트에서는 메타가 2배 넓어 기존 단언이 다 깨졌을 것이다).

## 결정

04-결정기록에 새로 적을 것은 없다 — 전부 D-42/D-12 구현이고 뒤집은 항목이 없다. 문서가 비워 둔 칸을 채운 것만:

1. **첫 줄은 한 줄, 줄이는 순서는 대상 → 도구, 동사는 불가침**(편차 ① 이 "디자인 판단 필요" 라고 남긴 칸).
   대상은 가운데를 줄여 확장자를 남긴다. 메타는 **아래로 내리지 않고** 같은 줄 오른쪽에 둔다(D12 5 그대로).
2. **"+N" 줄은 스크롤 밖 고정, `ask_parent` 안내 카드는 스크롤 영역 끝**(사양이 허용한 두 길 중 앞의 것).
   안내 카드는 세로로 길어서 고정하면 55% 안에서 카드 두 장을 밀어낸다 — 늘 보여야 하는 것은 "대기가 더 있다"
   는 사실(+N)이지 안내 카드가 아니다.
3. **보고 클램프는 표시 줄**이고, 잘린 글자는 위젯 트리에서도 뺀다(클리핑 아님). 복사·찾기 결과가
   보이는 것과 같아야 한다.
4. **`member.resize` 의 단일 진입점은 `TerminalCache.syncSize`** — "데몬이 아는 크기" 와 다를 때만 보낸다.
   덕분에 중복 resize 도 사라졌다.
