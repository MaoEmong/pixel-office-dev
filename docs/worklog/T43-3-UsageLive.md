# T43-3 — 사용량 표시 실기

- 날짜: 2026-09-21
- 마일스톤: M7
- 앞선 태스크: T43-1(데몬) · T43-2(앱) · T43-4(확인용 세션). 설계 `docs/design/사용량-표시.md`, 결정 D-45
- 환경: Claude Code 2.1.275(Max) · codex-cli 0.154.0(Pro) · 데몬 v1.0.0 · 창 1280×720 · 포트 7420~7422
- 캡처: `docs/worklog/img/T43-3-*.png`

## 목표

T43-1·T43-2·T43-4 는 전부 **실측 캡처를 픽스처로 쓴 단위 테스트**까지였다. 진짜로 띄워서
① 턴 없이도 칩이 채워지는가 ② 멤버가 한 턴 돌면 개체별 숫자가 맞는가 ③ **툴 밖에서 쓴 사용량**이 따라오는가
④ 연결 안 됨 표시 ⑤ 컨텍스트 경고 ⑥ 터미널 상태 줄 을 본다.

## 결론 먼저

전부 동작한다. 그리고 **실기에서만 나오는 결함 하나를 잡았다** — T43-1 이 statusLine 을 주입한 뒤로
**Claude 멤버의 지시 큐가 통째로 막혀 있었다**(아래 "발견한 결함 ①"). 실기를 안 했으면 못 봤다.

### 데몬 화면 vs CLI 자기 화면 (독립 세션으로 대조)

데몬과 무관한 **별도 세션**을 띄워 같은 슬래시 명령을 직접 읽었다(모델 턴 0).

| 값 | CLI 화면(독립 세션, 18:44) | 데몬 확인용 세션(18:42) |
|---|---|---|
| Claude `Current session` | `77% used` / `Resets 8:59pm (Asia/Seoul)` | 76% used / `2026-09-21T11:59:00Z`(= 20:59 KST) |
| Claude `Current week (all models)` | `62% used` / `Resets Sep 23, 11:59am (Asia/Seoul)` | **62% used** / `2026-09-23T02:59:00Z`(= 9/23 11:59 KST) |
| Claude `Current week (Fable)` | `56% used` / 같은 리셋 | **56% used** / 같은 ISO |
| Codex `Weekly limit` | `77% left (resets 14:02 on 28 Sep)` | 78% left(= 22% used) / `2026-09-28T05:02:00Z`(= 14:02 KST) |
| Codex `Account` | `<이메일> (Pro)` | 요금제 `Pro` 만 — **이메일은 읽지 않는다**(D-45 ②) |

주간·모델별은 **완전히 일치**한다. 5시간·Codex 주간의 1%p 차이는 두 판 사이 2분 동안 실제로 더 쓴 것이다
(5시간 한도는 그 시간대에 빠르게 오르고 있었다). 리셋 시각은 타임존 변환까지 맞는다.

### 관찰 — Claude 멤버의 "누적 토큰" 은 첫 턴 직후엔 안 나온다

표의 Claude 행이 `토큰 —` 인 것은 버그가 아니다. 누적 토큰은 transcript 의 `type:"cost-state"` 줄에서 오는데,
그 줄은 CLI 가 **주기적으로** 쓴다 — 짧은 턴 한 번 뒤의 transcript 를 열어 보니 `cost-state` 가 **0개**였다.
그동안 컨텍스트와 비용은 statusLine 이 바로 주므로 화면이 비지는 않는다. Codex 는 rollout 이 턴마다
`total_token_usage` 를 주므로 첫 턴부터 토큰이 나온다.

## 확인 3 — 툴 밖에서 쓴 사용량이 따라오는가

**따라온다.** 다만 **Codex 쪽은 한 번의 작은 실행으로는 표시 해상도(1%p)를 못 넘는다** — 그래서 두 가지로 보였다.

### (a) Codex — 데몬 밖에서 `codex exec` 한 번

```
19:06:53  (데몬 밖, sandbox 에서) codex exec "Reply with exactly: OK"  → 19:07:02 완료, tokens used 6,861
```

| 확인용 세션 판 | Codex 주간 |
|---|---|
| 18:58:53 (turn) | 75% 남음 |
| 19:06:54 (probe — exec 시작 1초 뒤라 **exec 이전 값**) | 74% 남음 |
| **19:11:57 (probe — exec 이후 첫 판)** | **74% 남음** (값 그대로, `updatedAt` 만 갱신) |
| 19:15:46 (probe) | **73% 남음** |

6,861 토큰은 주간 창의 1%p 에 한참 못 미친다 — **화면이 주는 해상도 자체가 정수 퍼센트**라 그 한 번을
콕 집어 보일 수는 없다. 대신 원자료를 직접 대조해 **확인용 세션이 실제로 다시 읽고 있다**는 것을 확인했다
(19:12:45, 데몬과 무관한 독립 세션):

```
│  Weekly limit:  [███████████████░░░░░] 74% left (resets 14:02 on 28 Sep) │      ← CLI 화면
codex   … 주간 74% 남음 … 측정 2026-09-21T10:11:56.994Z(probe)                     ← 데몬(같은 값)
```

그리고 **툴 안의 Codex 멤버는 18:58 이후 한 턴도 돌지 않았는데** 주간이 75 → 74 → 73 으로 내려갔다.
그 사이 이 계정의 Codex 소비는 (a) 18:58 의 멤버 턴 하나와 (b) **툴 밖의 `codex exec`** 뿐이다.

### (b) Claude — 훨씬 또렷하다

같은 시간대에 이 기계에서는 **툴 밖의 Claude Code 세션**(이 작업을 하고 있는 세션)이 계속 돌고 있었다.
툴 안의 Claude 멤버는 18:58 이후 한 턴도 돌지 않았는데 **5시간 한도가 계속 내려갔다**:

| 확인용 세션 판 | Claude 5시간 | 주간 |
|---|---|---|
| 18:42:08 | 24% 남음 | 38% |
| 18:56:45 | 23% 남음 | 39% |
| 19:01:47 | 22% 남음 | 38% |
| 19:12:21 | **20% 남음** | 38% |

19:12:45 의 독립 CLI 화면도 `Current session 80% used`(= 20% 남음) · `Current week 62% used`(= 38% 남음) ·
`Current week (Fable) 56% used`(= 44% 남음) 로 **세 값 모두 정확히 일치**했다.

→ **턴이 없어도, 툴 밖에서 쓴 것도 5분 안에 반영된다**. T43-4 가 메우려던 구멍이 실제로 메워졌다.

## 확인 5 — 컨텍스트 경고 막대(≥70%)

**실기로 재현하지 않았다.** 1M 창의 70% = 70만 토큰이라 일부러 채우려면 할당량을 크게 쓴다.
대신 기존 위젯·페인터 테스트로만 확인한다(`dev/app/test/usage/usage_canvas_test.dart` 7건):
69% → 안 그림 · 70% → 주황 · 90% → 빨강 · 퇴근/오류 멤버 → 안 그림 · 자리(모니터 아랫변)와 두께 3px.
실기 캡처에서도 컨텍스트가 5~9% 라 **막대가 그려지지 않은 것**이 설계대로다(빼기 원칙).

## 발견한 결함

### ① (심각) statusLine 을 주입하면 `? for shortcuts` 가 사라져 **Claude 멤버 큐가 영영 막힌다**

- **증상**: 부서를 만들고 `say 반장 …` 을 했는데 6분이 지나도 `task#58 queued` 그대로. 멤버 상태는 `idle`,
  화면도 멀쩡한 프롬프트. 지시가 pty 에 **한 글자도** 들어가지 않았다.
- **원인**: `InputQueue` 는 `ScreenModel.promptReady()` 가 true 여야 flush 한다. Claude 맵의 준비 신호는
  `? for shortcuts` / `shift+tab to cycle` 인데, **T43-1 이 모든 Claude 멤버 세션에 statusLine 을 주입한 뒤로
  그 힌트가 사라진다** — 우리 상태 줄이 그 자리를 쓰고 힌트 줄이 `⏸ manual mode on · ← for agents` 로 짧아진다.
  화면 평문을 떠서 확인:
  ```
  promptReady = false | busy = false | dialog = none
  bottom: ["────…", "❯ ", "────…", "  주간 38% 남음", "  ⏸ manual mode on · ← for agents"]
  ```
  같은 시각 `--settings` 없이 띄운 독립 세션에는 `? for shortcuts` 가 그대로 있었다 — **statusLine 주입이 원인**이 맞다.
- **왜 지금까지 안 걸렸나**: T43-1 은 실기를 하지 않았고(그 worklog "남은 것" 에 그렇게 적혀 있다),
  T43-2 는 가짜 데몬만 썼다. 단위 테스트의 Claude 준비 화면 픽스처는 statusLine 이 없던 시절 캡처다.
- **고친 것**(데이터만, 코드 아님): `src/tui-maps/claude-2.1.json` 의 `promptReady.anyOf` 에 `←\s*for agents\s*$` 를
  더하고 `scanLines` 를 4 → 5 로 올렸다(우리 상태 줄이 한 줄 더 차지한다). 모드 표시(`⏸ manual mode on` /
  `⏵⏵ accept edits on` …)는 바뀌므로 쓰지 않았다. 실물 픽스처
  `test/screen/fixtures/claude/ready-statusline.txt` 와 테스트 1건을 추가했다.
- **고친 뒤**: 같은 지시가 **즉시** 들어가 12초 만에 끝났다.

### ② (사소) Codex 요금제 표기가 출처에 따라 다르다

확인용 세션 화면은 `Account: … (Pro)` 라 **`Pro`**, rollout `plan_type` 은 **`pro`**. 마지막에 온 쪽이 이겨서
콘솔·팝오버의 "요금제" 글자가 `Pro` ↔ `pro` 로 왔다 갔다 한다. 값의 뜻은 같아 이번에는 두었다 — 고친다면
