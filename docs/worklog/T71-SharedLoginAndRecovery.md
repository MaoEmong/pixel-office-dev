# T71 — 터미널 로그인 공유와 앱 내 로그인·복구

## 확인된 원인

일반 터미널의 Claude 로그인은 유효했지만 부장 세션에 처음 복사한 로그인 정보는 만료되어 있었다. 실제 터미널에는 `Login expired · Please run /login`이 떴고, 앱은 답변 없는 유휴 상태를 ‘답변 준비 중’으로 표시했다.

## 변경

- 실행 전 최신 로그인을 반영하고 실행 중 터미널 재로그인·앱 세션 갱신을 다른 세션에 공유한다. 만료되거나 쓰다 만 인증 파일은 다른 유효한 로그인 위에 덮지 않는다. 설정과 대화 기록은 프로젝트별로 유지한다.
- 실제 인증 실패 출력을 감지해 멤버 오류와 팝업으로 알린다. 기존 업무를 취소하지 않고 아직 처리하지 못한 입력을 보관한다.
- 팝업에 해당 멤버의 터미널을 여는 버튼을 제공한다. 로그인 오류 배너는 ‘종료됨’이나 ‘재고용’ 대신 로그인 복구를 안내한다.
- 앱 터미널의 ‘로그인’은 실제 CLI 로그인 프로그램을 표시한다. ‘로그인 연결 · 요청 재시도’는 인증을 검사한 뒤 같은 대화를 연결하고 답변하지 못한 요청을 이어간다. 로그인 승인 자체는 사용자가 브라우저/터미널에서 처리한다.
- 터미널 명령 입력란은 `/help`, `/status` 같은 명령을 직접 전송한다. 일반 터미널 키 입력도 유지한다.

## 검사

- 유효한 전역 로그인과 만료된 프로젝트 로그인, 양방향 갱신, 여러 세션, 부분 저장 실패, 대화 파일 보존을 검사했다.
- 인증 오류를 넣은 실제 화면 처리에서 오류 상태·살아 있는 터미널·기존 작업 보존을 확인했다. 복구 시 요청이 한 번 재전송되고 대화 행이 중복되지 않는지 검사했다.
- 로그인 프로그램 실행·키 입력·로그인 후 재연결, 잘못된 명령 및 작업 중 로그인 거부를 검사했다.
- 앱에서 로그인·복구·명령 버튼과 팝업의 해당 터미널 이동을 검사했다.

CLI 동작 확인: [Claude 로그인 문서](https://code.claude.com/docs/en/authentication), [Codex 공식 CLI 문서](https://developers.openai.com/codex/cli/reference).

## 결과와 실제 복구

- 작업 관리 코드 검사 통과. 전체 검사 1,258건 통과·15건 건너뜀. 앱 코드 검사 문제 없음. 전체 검사 826건 통과·1건 건너뜀. Windows 실행 파일 생성 성공.
- 기존 기록을 DB 백업으로 보관하고, 모든 AI가 유휴이며 미처리 승인·작업이 없는 시점에 수정본을 적용했다. 네 AI는 같은 대화 ID로 돌아왔으며 요청 만료는 없었다.
- 실제 부장의 프로젝트 로그인과 일반 터미널 로그인 정보가 같고 만료되지 않았음을 확인했다. 인증 값 자체는 출력하지 않았다.
- 기존 논의 `w_39306023-d22d-439a-9ed2-836b1a025693`와 사용자 요청 ‘다음작업 진행해’를 유지하고 재시도했다. 부장이 실제 응답을 완료해 사용자 메시지 1개·답변 1개가 됐다.
- 부장은 2단계 작업안과 선택 사항 세 가지를 제시했다. 새 업무의 제품 결정을 대신 승인하거나 작업 기록을 새로 만들지 않았다. 앱에서 답변하고 작업을 시작할 수 있다.
