# T59 — 예측 가능한 실패 후처리

- [x] 기본 엔진을 부장 엔진으로 제한하고 사용자 허용 목록을 DB에 영속
- [x] 생성·재고용·재시작·복구·새 지시·위임에 엔진 정책 적용
- [x] MCP 고용에서 설치·인증 검사 및 비동기 실패 응답
- [x] 원격 서버 기동 실패를 로컬 작업과 분리하고 재시도 제공
- [x] 설정 저장 실패 안내·재시도, 계속 일하기 설정 저장 실패 시 이전 값 유지
- [x] 앱 잠금 저장 실패 시 안내·재시도 화면
- [x] 출근 부분 실패 시 error 상태·미배정 작업 정리 및 세션 종료
- [x] 실패 주입 회귀 테스트·전체 검사
- [x] 빌드·직접 GUI 조작 확인

모바일 실기기 검증은 사용자 요청대로 보류한다. 결제 여부를 CLI 로그인 여부로 추정하지 않는다.
기본은 부장과 같은 엔진만 사용하며 환경 점검 화면에서 Claude/Codex/둘 다를 명시적으로 선택할 수 있다.
정책 변경은 실행 중 작업을 강제 종료하지 않으며 이후 생성·복구·지시를 제한한다.

## 검증

- 백엔드 전체: 1,216 통과, 16 건너뜀. 새 실패 주입 테스트 8개 포함.
- Flutter 전체: 760 통과, 1 건너뜀. 최종 설정/환경/원격 후처리 테스트 14개 재검사 통과.
- TypeScript typecheck, Flutter analyze 통과. Windows release 빌드 성공.
- 테스트 전용 데이터 폴더와 별도 포트에서 실제 앱을 조작했다.
  app.lock 경로를 폴더로 막아 실패 안내를 확인하고 경로 복구 후 '다시 시도'로 기동했다.
  app-ui.json 경로를 폴더로 막아 계속 일하기 저장 실패를 만들고 '다시 저장' 후 파일 기록·스위치 반영을 확인했다.
  다시 끄면서 기존 설정 파일 교체 저장도 확인했다.
  원격 포트를 점유한 상태에서도 로컬 RPC·앱이 동작했고, 충돌 해소 후 화면의 재시도 버튼으로 HTTP 200 및 available=true를 확인했다.
  환경 점검에서 Claude만 사용을 선택하고 RPC에서 저장된 허용 목록을 확인했다.
- 직접 조작 증거는 로컬 `.local/t59-{lock-failure,prefs-failure,remote-failure,engine-policy}.png`에 보관한다.
  사용자 실제 데이터 폴더의 인증·작업 기록과 원격 등록은 변경하지 않았다.
- 테스트 앱을 정상 종료하고 최종 빌드를 기존 데이터 폴더로 실행했다.
  기존 sandbox 부장이 idle로 복구됐고 대기 0건, 원격 서버 available=true를 확인했다.

아직 전체 재현을 완료하지 않은 범위: 실행 도중 인증 만료·모델 사용량 제한·서버 장애,
CLI 화면 변경, 전체 디스크 고갈 및 파일 시스템 자체 손상. 상태 확인 성공은 모델 요청 성공을 보장하지 않는다.
