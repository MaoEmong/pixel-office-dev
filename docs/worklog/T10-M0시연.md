## 목표
M0 데몬이 실제 Claude Code 두 세션을 콘솔 클라이언트만으로 지휘할 수 있음을 한 번에 시연하고, hook 보류 상한(86400)을 10분 초과 보류로 확인한다.

## 시나리오와 결과 (실제 출력 발췌)

데몬: `npx tsx src/index.ts` (기본 포트 7420/7421, 데이터 `%LOCALAPPDATA%\pixel-office`). 팀 `demo` cwd = `dev/spike-0/sandbox`.

### 1. 고용 2명 → 지시 2건 → 허가 대기·질문 대기
```
po> hire demo claude 하루
출근: m_4a2df8958509  하루 [claude] starting  pid=8136
po> hire demo claude 모시
출근: m_36531b8400a7  모시 [claude] starting  pid=23408
po> say 하루 셸 명령 "echo t10 > t10.txt"를 실행해줘. 다른 건 하지 마.
task#2 → 하루
po> say 모시 AskUserQuestion 도구로 나에게 "점심 뭐 먹을까?"라고 물어봐. 옵션은 김밥, 라면. …
task#3 → 모시
status 하루 → idle / status 모시 → idle          (두 세션 준비, 약 3초)
#10 thinking 하루 [TASK#2 from user] …
#12 running 하루 Bash echo t10 > t10.txt — Write t10 to t10.txt

status 하루 → waiting_approval / status 모시 → waiting_answer
```

### 2. 재접속(새 클라이언트) → 스냅샷에 pending 2건 → 답변·허가
```
데몬 v1.0.0 연결됨 — seq=14
열린 pending 2건
  a_c665acfffac9  approval  하루  Bash echo t10 > t10.txt
  q_ae69582d816f  question  모시  점심 뭐 먹을까? [김밥|라면]
po> answer q_ae69582d816f 라면      → status 모시 → working
po> allow a_c665acfffac9            → status 하루 → working
#15 text 모시 오늘 점심은 라면으로 정했어요. 🍜
#16 idle 모시
$ cat sandbox/t10.txt → t10
```
질문 답은 hook 결정(`updatedInput.answers`)으로 들어갔고 TUI 메뉴는 뜨지 않았다. 허가도 마찬가지.

### 3. 데몬 강제 종료 → 재시작 복구
```
$ taskkill /PID 24296 /F
$ npx tsx src/index.ts
[office] recover 하루(m_4a2df8958509): --resume 66676fbf-…, assigned 0, requeued 0, expired 0
[office] 복구: 모시 의 이전 pid 23408 를 건드리지 않음 — process name bash.exe does not look like claude
[office] recover 모시(m_36531b8400a7): --resume 357de20d-…, assigned 0, requeued 0, expired 0
[office] 복구: 2명 재개, 0건 만료
po> say 모시 아까 정한 점심 메뉴가 뭐였는지 한 줄로 말해줘.
#32 text 모시 아까 정한 점심 메뉴는 라면이었어요. 🍜
```
- 이번엔 `taskkill /F`로 죽였더니 자식 `claude.exe`도 같이 죽었다(T09에서는 `process.kill`로 죽였을 때 살아남음). **둘 다 가능**하므로 D-17의 유령 정리는 유지. PID 재사용 가드(23408이 bash.exe가 됨)가 실제로 동작했다.
- resume 후 이전 대화 맥락("라면") 유지 확인.

### 4. hook 보류 10분 초과 (D-16 검증)
```
po> say 하루 셸 명령 "echo hold10 > hold10.txt"를 실행해줘. 다른 건 하지 마.
#30 thinking … → (waiting_approval a_…)   보류 시작 01:34:20
```
```
checked at 01:45:57 (hold started 01:34:20)   ← 11분 37초 경과
열린 pending 1건
  a_69b57750bc11  approval  하루  Bash echo hold10 > hold10.txt
po> allow a_69b57750bc11 → 실행 → hold10.txt 생성
```
**`timeout: 86400`이 받아들여져 10분(구 600초)을 넘겨도 hook이 유지된다.** error 이벤트 없음, 허가 후 정상 실행.

## 검증
- 위 1~4 전부 실제 데몬·실제 `claude.exe` 두 세션으로 수행. 명령·출력은 콘솔 클라이언트(`npm run cli -- --exec …`) 그대로.
- 전체 테스트: `npx tsc --noEmit` 클린, `npx tsx --test test/**/*.test.ts` → 164 pass / 0 fail / 3 skipped(PIXEL_IT 통합).
- M0 완료 기준 "콘솔에서 고용→지시→허가→재접속 replay" + 재시작 복구 + 10분 초과 보류 모두 충족.

## 발견한 함정
- 콘솔 `--wait-idle`은 허가 대기 상태에서는 당연히 타임아웃된다 — 시연 스크립트에서 pending 확인용으로만 사용.
- 같은 이름(하루)의 exited 멤버가 남아 있으면 이름 해석이 살아 있는 쪽을 우선한다(T08 규칙) — 동작 확인.
