# 작업 상태·자동 단계 진행·실행 사전 검사 정리 (2026-10-16)

이전 정리 커밋 `cf5007f` 이후 추가한 변경을 정리한다.
그 이전 작업은 [첫 작업 정리](2026-10-16-ChangesSummary.md)를 참고한다.

## 승인과 질문의 대상·처리 상태

- 승인이 끝난 요청은 화면 상태에서도 즉시 정리해, 캐릭터가 계속 사용자 책상에서 승인 대기하는 것으로 보이지 않게 했다.
- 팀원이 상사에게 보낸 질문은 받는 사람과 질문 방향을 표시한다. 사용자에게 온 질문·승인 요청과 구분한다.
- 상사에게 보낸 내부 질문은 저장된 기록으로 다시 전달한다. 앱이나 상사 세션을 다시 시작해도 질문이 사라지지 않는다.
- 상사의 답변도 전달 완료까지 저장한다. 전달 전에 재시작돼도 답을 다시 보내며 이미 전달한 답은 반복하지 않는다.
- 상사가 답변 도구를 빠뜨리면 제한된 횟수로 다시 요청하고, 계속 누락되면 부장에게 내부 조정을 요청한다.
- 답을 받았다고 이미 끝난 구현 작업을 다시 시작하지 않는다. 실제로 남은 배정 업무가 있으면 그 복구 지시는 유지한다.

## 명령 제출과 로그인 안내

- Codex의 작업 중 표시가 여러 줄로 나뉘는 경우도 확인해, 이미 받은 지시를 제출 실패로 오인하거나 Enter를 반복하지 않게 했다.
- CLI 화면이 작업 중이면 새 지시를 보낼 준비가 됐다고 판정하지 않는다.
- 작업 중 사용할 수 없는 로그인 갱신 버튼에는 대기 이유를 표시한다. 작업 보호 안내를 로그인 만료 오류로 표현하지 않는다.
- 긴 터미널 화면을 읽는 로그인 오류 판정에서 불필요한 반복 탐색을 없애 작업 관리 프로그램이 멎는 문제를 줄였다.

## 부장이 판단하는 단계 진행

- 목표가 정리되면 부장이 작업을 시작하고, 회의에서 팀별 업무와 완료 기준을 확정한다.
- 담당 업무가 모두 끝나면 부장이 검증하고 단계 완료를 기록한다. 남은 목표가 있으면 다음 회의를 시작하고, 모두 충족했을 때 전체 완료한다.
- 단계마다 완료한 일, 검증 근거, 당시 회의 결정·팀별 보고·담당자 이름, 다음 단계를 저장한다.
- 화면의 최근 완료 안내와 '단계 기록' 탭에서 중간 결과를 다시 확인할 수 있다.
- 단계 진행을 위한 사용자 버튼 확인은 반복해서 요구하지 않는다. 실제 명령 승인과 필요한 로그인 절차는 유지한다.
- 재시작 후에도 미완료 검증 요청을 복구한다. 같은 단계 기록을 다시 제출해도 다음 단계가 중복 생성되지 않는다.

## 중단된 업무와 정상 팀의 작업

- 한 팀이 실패해도 이미 승인된 다른 팀의 명령 실행, 자기 팀원에게의 업무 배정, 완료 보고는 계속할 수 있다.
- 중단된 팀이나 부장의 새 업무 배정까지 임의로 허용하지 않는다.
- 재개할 때 기존 회의와 완료 기준을 보존하며, 중단 보고가 확인된 업무만 새 작업으로 이어간다.
- 진행 중이거나 끝난 다른 업무를 중복 배정하지 않는다. 이전 중단 보고는 기존 작업 기록에 남는다.

## 읽기 쉬운 화면과 오류 복구 동선

- 오른쪽 알림 영역이 로그·터미널을 밀어내지 않게 읽기 공간을 확보하고, 작은 창에서는 알림을 접어 표시한다.
- '크게 보기'로 질문·승인·제출 상태를 넓은 창에서 확인할 수 있다.
- 확대 창에서 터미널로 이동하면 팝업도 닫아 실제 터미널을 볼 수 있게 했다. 일반 패널에서는 화면 자체를 닫지 않는다.
- 로그는 시간·종류와 내용을 나누고 내용을 눌러 원문을 크게 볼 수 있게 했다. 재시작·연결 복구 기록도 읽기 쉬운 문구로 표시한다.
- 복구된 질문의 옛 만료 안내가 답변 뒤 다시 나타나지 않게 했다. 이후 실제로 새 만료가 발생한 경우에는 안내를 유지한다.

## Windows Codex 실행 사전 검사

- 이 PC에서 재현된 기존 Windows 실행 권한 오류에 대응해 지원되는 환경에서는 MXC를 우선 사용한다.
- 계획 확정·팀원 업무 배정·중단 업무 재개 전에 담당자의 로그인과 실제 명령 실행을 검사한다.
- 실제 멤버의 작업 폴더와 세션 설정을 사용하며 AI 요청이나 프로젝트 명령은 실행하지 않는다.
- 응답 시간 초과는 고정된 검사 명령만 한 번 더 확인한다. 계속 실패하면 업무를 보내기 전에 원인과 다음 조치를 팝업으로 알린다.
- Windows 권한 오류, 실행 준비 지연, 세션 폴더 누락, 점검 명령을 지원하지 않는 CLI 버전을 구분한다.
- 같은 점검이 동시에 들어오면 실행을 공유하고, 다음 시도에서는 복구된 상태를 새로 확인한다.
- 권한이나 승인 절차를 임의로 해제하지 않는다. 원시 명령 출력과 인증 정보는 점검 결과에 넣지 않는다.

- 실제 Codex 멤버 5명의 세션 설정으로 명령 실행 사전 검사가 통과했다.
- 작업 폴더 조회 성공과 작업 폴더 밖 일반 폴더 쓰기 차단을 확인했다.

- 로그인·실행 사전 검사가 통과해도 이후 서비스 장애·로그인 만료·사용량 제한까지 보장하지는 않는다.

실행 중인 업무와 승인 대기를 보호하기 위해 커밋·푸시 과정에서 앱을 재시작하지 않는다.
현재 실행 중인 프로그램에 아직 반영되지 않은 사전 검사와 검토 보완은 다음 데몬·앱 실행부터 적용된다.
